## Context

The generated `/workspace/AGENTS.md` (DL-037) tells the agent that each CLI is "already authenticated" and that its token may be scoped to a subset of repositories. It says nothing about what the agent should do when a forge command answers 401, 403 or 404. The credential is managed outside the agent's reach: renewed by the server (DL-021) and attached by the proxy only to the requests it allows (DL-034), and the placeholder the CLI holds cannot be replaced by anything the agent can do. `gh` answers an unauthenticated request with `Try authenticating with: gh auth login -h github.com`, so an agent follows that, finds it cannot, and stops, asking the person for a token. The agent that met this reported that it needed a refreshed token and could not handle it itself (see DL-107).

## Decision

`AgentsMarkdown` adds a section, after the one on opening pull requests, when any repository is listed. It says, in the agent's terms:

- the credentials here are managed by spov, not by the agent;
- a forge command that answers 401, 403 or 404 on something the agent would expect to reach is therefore not a sign that it must log in again: it does not run `gh auth login` or the CLI's equivalent, and does not ask the person for a token;
- it retries once in case the failure was transient, then reports the exact command and the exact error message, and carries on with whatever does not need it.

The text names no credential and makes no claim about where one is held or what keeps it current: a sandbox launched without the proxy holds it in the main container (DL-034), and only a GitHub App's token is renewed (DL-021). `TestTheGuideSaysARefusedForgeCommandIsNotAnExpiredToken` bans the words that would. It is guidance, not containment, as the generated guide always is (DL-039).

## Rationale

- The person can act on the exact command and error, and cannot act on "the token is invalid". A command the policy does not cover is a fix in spov, and it is found from the report.
- A retry covers a re-mint that has just landed (DL-021) without inviting a loop.
- Alternatives rejected: a separate sentence per CLI (the same advice for all three); telling the agent which endpoints are refused (the list changes with DL-034 and the guide would drift); saying the token is renewed (true only for a GitHub App).

## Consequences

- A session with a refused forge command should end in a report naming the command, not in a request for a token.
- The guide grows by one section for every session that has a repository.
- It makes no difference to a session with no repositories, whose guide is unchanged.
