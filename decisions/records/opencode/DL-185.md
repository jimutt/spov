## Context

A reasoning mode is one of a model's OpenCode variants. DL-159 reads them from a running sandbox, because OpenCode applies its own exceptions to models.dev's data and a re-derivation in spov would drift. Before a launch there is no sandbox to ask, so `/jobs/new`, `/sessions/new`, Settings, the CLI and scheduled jobs cannot offer a mode. The modes are a function of the OpenCode build and the models it knows, and the pinned binary lists them for every provider it holds a key for, a placeholder key being enough (`TestIntegrationLocalOpenCodeProbeModelList`: 105 models, 98 with variants, from two placeholder keys at 2.4.2).

## Decision

- The modes of the pinned build are a snapshot committed with the pin: `internal/modelcat/variants.json`, `{"opencode": "<version>", "models": {"provider/model": ["low", "high", ...]}}`, embedded in the binary and read by `modelcat`. It is written by the pinned binary itself, never by spov's own reading of models.dev: `SPOV_PROBE=1 go test -tags integration ./internal/server/ -run WriteTheVariantSnapshot` starts it isolated, as the probes do, with a placeholder for every key variable in `prep.ProviderKeyEnvs` (the console's `OPENCODE_API_KEY` among them) and models.dev's fetch off (`OPENCODE_DISABLE_MODELS_FETCH=1`, with the network closed), so the list is the binary's own and the same on every run, waits for the list as the recorder does (DL-183), and writes what `parseModelVariants` keeps, for the providers in spov's catalogue only, keys sorted.
- At 2.4.2 it holds 463 models of all ten carried providers, 32 KB. `TestTheVariantSnapshotIsThePinnedBuilds` fails until the snapshot's `opencode` equals `DefaultOpenCodeVersion`, so a bump cannot land without it; the snapshot is bounded by `MaxModelVariantsBytes` like any kept list.
- "Bumping the pin" gains the step after the contract: regenerate the snapshot and put its diff in the PR.

## Rationale

The binary is the one source DL-159 trusts; running it at bump time gives the same answer a sandbox would for the models it knew then, with no network, no real key and nothing re-derived. A file beside the pin moves with it and is reviewed like the contract.

## Consequences

- A model released after the bump is not in the snapshot; DL-186 covers it from real sandboxes.
- A provider the binary lists only after a sign-in it cannot get with a placeholder is missing from the snapshot, and offers only its default until a sandbox reports it.
