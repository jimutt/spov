## Context

A sandbox's global OpenCode config (`~/.config/opencode/opencode.json`) is written by spov (DL-038), so a person had no way to bring the plugins they use with their own OpenCode; only a repository's `opencode.json` could add any, and only when the session ran inside it (DL-170). spov supports OpenCode 2 only, whose config key is `plugins` (an array of npm package specs) and whose plugin API is not that of 1.x.

## Decision

- `sandbox.plugins` is a list of npm package specs (`name`, `@scope/name`, either with `@version`, a tag or a semver range) in the user file, a project file or a sandbox template, and `--plugin` on `spov fly` (repeatable). The flag replaces the config's list; a template's list applies when the request names none, as its other fields do (DL-120). A project file may set it: a repository can already add plugins through its own `opencode.json`.
- The request carries `plugins`; `validateRequest` checks each spec (`opencode.CheckPluginSpec`: a valid npm name, an optional version of at most 64 safe characters, no URL, path, git or file spec, at most `MaxPlugins` = 16) and a template is checked the same way when written. It is stored with the request, shown on the session's view and page, and kept on resume.
- The entrypoint writes the list as the global config's `plugins` key, in an interactive session's config only (`SandboxConfigJSON`). OpenCode merges it with a repository's own `plugins` when the session runs inside one. OpenCode installs them from npm at the session's first conversation; a snapshot resume keeps the installed copies (DL-084).
- A job's config carries none: a job's permission policy allows only the actions its kind needs (DL-040), and a plugin's tools are not among them, so plugins in jobs wait for a decision of their own.

## Rationale

The global config is where `opencode plugin add` puts a plugin on a person's own machine, so it applies wherever the session lands, including a session with several repositories. Package specs only, because a URL or a path would let the list fetch or run something no registry names.

## Consequences

- `TestAPluginListReachesTheSandboxConfig`, `TestCheckPluginSpec`, `TestATemplatesPluginsApplyWhenTheRequestNamesNone` and the CLI's flag test guard it.
- `docs/plugins.md` is the reader's page.
