## Context

spov writes its guide for the agent to `/workspace/AGENTS.md`: the repositories and their forge CLIs, the scratchpad, what a refused forge command means (DL-108), the toolchain, and for a job its pull request or report sections. DL-037 relied on OpenCode finding it by walking up from the session's directory, which spike S11 measured in `/workspace` itself, a directory with no git root.

Inside a cloned repository the search stops at the repository's root: OpenCode looks for `AGENTS.md` from the session's directory up to the project's directory, the git top level. Measured on OpenCode 2.3.0 in a Modal sandbox started in `/workspace/notes-app`: the agent had no scratchpad section, no rule for a 401, 403 or 404, and no `AGENTS.md` loaded at all. Synced launches, a configured `landing` and sync jobs have started inside a repository all along, and DL-170 makes it the default for a session with one repository.

With `instructions: ["/workspace/AGENTS.md"]` added to the same sandbox's config, the next turn had the guide.

## Decision

- When the session works inside a repository and spov writes the guide, the global OpenCode config lists it under `instructions` (`Entrypoint.guideInstructions`), in an interactive session's config and a job's alike. Where the session works is `Entrypoint.WorksIn`, the launch's landing, not the directory the server starts in: a local-only synced session starts its server in `/workspace` because its repository is seeded afterwards, yet its conversations work in the repository.
- The guide says which: inside a repository, that its own `AGENTS.md` and OpenCode configuration are loaded and paths are relative to it; at the root, that no repository's instructions are loaded (`agentsMarkdown`).
- A session that starts in `/workspace` does not list it: OpenCode finds the guide there itself, and listing it as well would load it twice.

## Rationale

`instructions` is OpenCode's own way to add an instruction file beyond the project's, and it reads it wherever the session runs. The guide stays one file at one path, so the agent and the docs can still name `/workspace/AGENTS.md`.

## Consequences

- `TestTheGuideIsListedWhenTheSessionStartsInARepository` and `TestALocalOnlySyncedSessionListsTheGuide` guard it. The measurement repeats in the end-to-end check of a synced session.
