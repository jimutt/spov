## Context

DL-035 checks every request spov sends against the pinned build's OpenAPI document, and leaves event payloads to probes, because the document did not describe them. The 2.3.0 document does: `V2Event` is a union of one schema per event type (`session.inbox.enqueued`, `session.execution.succeeded`, `permission.asked` and the rest), and `SessionLogItem` describes the items of the session log. Several guards exist only because a hand-built frame in the wrong shape passes a test that real frames fail (gate 3's permission pairing, the stop marker's path, the tool-call projection).

The document also uses two schema keywords the validator does not know, `contentSchema` and `patternProperties`.

## Decision

- The contract package gains `CheckEvent(frame)`: it reads the frame's `type`, finds that type's schema in the document's event union and validates the frame against it. A type the document does not list is an error, except a frame whose type begins `spov.`, which is spov's own and is not checked. A type is found by its schema's `type` enum, or by its pattern (`rpc.*`), never by the schema's name, which differs for some (`SessionStatusUpdated` is `session.status`). `CheckLogItem` does the same against `SessionLogItem`, the durable events and `log.synced`.
- The validator checks `patternProperties` (each property whose name matches a pattern against that pattern's schema, and such a property does not count as additional) and ignores `contentSchema`, which describes the decoded content of a string spov never decodes through the validator. A boolean subschema is read as JSON Schema reads it: `true` accepts any value and `false` none. `TestTheValidatorKnowsEveryKeywordTheDocumentUses` also compiles every `pattern` and `patternProperties` key under Go's regexp, so a pattern Go cannot read fails at the bump rather than on the first value it meets.
- Go test helpers that build OpenCode event frames validate what they build, and fail the test on a frame the document refuses:
  - in `internal/server`: the recorder's fake stream (`fakeSandbox.send`, the only way a test streams a frame), `durableFrameFor`, `seedEvent` for any row not spov's, `projectString`, the session-log fake's `logItem`, and the job lifecycle's `putFrame`;
  - in `internal/jobs`: `followFixture.put` and every frame builder its tests share (`inboxItemRaw`, `deliveredRaw`, `inboxFrame`, `inboxTextRaw`, `stopFrame`, `interruptEvent`, `putAsk`);
  - in the scenario harness: `scenarioServer.frame`, through which every scenario stores a frame (`jobOpenCode` serves files and the message log, and streams no frame).
  - Fixtures written inline go through `contract.Frame` (a whole frame) or `contract.Event` (data in the envelope the document gives its type: an id, a creation time and, for a durable type, its place at the version the type allows).
- A fixture that deliberately carries a frame no build sends (cut off, an earlier build's flattened envelope, a field under another name, a type no inbox holds) says so through `contract.Unchecked(raw, why)`, which refuses an empty reason. A spov row under an OpenCode name is one of these.
- The local probes validate every frame the pinned binary streams during their run (`frameAudit` in `probe_integration_test.go`, shared by `TestIntegrationLocalOpenCodeProbe`, the S-Q1, S-F1, S-SA1, S-SA2 and S-TR1 spikes), and S-TR1 also validates each item of a conversation's durable log, so a document that disagrees with the build is found at a bump. At 2.3.0 every frame the probes stream passes, so no field or type is exempted.
- The package stays test-only (its depguard rule is unchanged). Nothing at run time validates a frame; the recorder keeps storing whatever a sandbox sends.
- Not covered: the browser's fixtures; the plugin's tests, whose events are JavaScript literals handed to the plugin's hook; and the Modal integration tests, which read real frames from a sandbox and build none.

## Rationale

The shapes spov reads are the ones its tests build by hand, and a published schema is a cheaper and wider check than a probe per shape. Checking at the helpers covers every test that uses them without touching each test. Run-time validation is left out because a frame spov does not understand must still be recorded (DL-018), and a new event must still be shown (DL-058).

## Consequences

- A bump's contract refresh now also fails tests whose frames the new build would not send.
- Existing fixtures that fail the check are corrected to the published shape, or marked unchecked with the reason. At 2.3.0 the corrections were missing envelope fields (`id`, `created`, `durable`), data fields an event requires (`assistantMessageID`, `started`, `model` and `agent` on a step, `inboxID` and `delivery` on an inbox item, `action` and `resources` on a permission, `location` on `session.created`), identifiers of the wrong form (`p1` for a permission, `inb_` for an inbox item, a conversation not named `ses…`), an interrupt reason the build does not have (`aborted`), a durable version (2 on `session.tool.success`), and event types no 2.3.0 build sends (`message.part.delta`). Every production reader read the corrected shapes unchanged.
- The probes that exist to measure behaviour (ordering, the inbox, subagents) stay; the ones that only measured a shape can be retired as their shapes are covered.
