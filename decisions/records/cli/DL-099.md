## Context

DL-080 put the install script first in the README's install section and kept building from source below it. The README had grown into the whole manual: install, building from source, prerequisites and every command's reference, in that order, before a reader learned what spov is for. The owner asked, on 2026-11-07, that the README make clear what spov is, the value it gives and how to get started, before any configuration, and that the local build steps not be prominent.

## Decision

This amends DL-080's placement of building from source.

- The README holds what spov is, why to use it, a quick start (install, Modal and the sandbox image, a forge, a model, `spov fly`), what to do when the first run fails, a short tour of sessions, jobs and the dashboard, how it works, a configuration example and an index of the guides.
- The detail lives in guides under `docs/`: `sessions.md`, `jobs.md`, `credentials.md`, `sandbox.md`, `server.md` and `development.md`, beside the existing references.
- Building from source moves to `docs/development.md`, which the README links under Contributing. The README's install step keeps DL-080's form: the script, `less install.sh` before running it, and the piped `curl … | sh` for those who trust it unread.

## Consequences

- A first-time user reads one page to a working `spov fly`; a contributor follows one link to build.
- A guide that restates a rule must be updated with it; the README's quick start in particular must follow any change to what a first run needs (as the sandbox image step does today).
