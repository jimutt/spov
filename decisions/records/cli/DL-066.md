## Context

`git.MaxSyncBundleBytes` (16 MiB) bounds the raw git bundle the CLI builds for a synced launch (`BundleHEAD`, `bundleUnpushedCommits`; DL-027). The request carries it base64-encoded, and `Service.validate` (`internal/server/service.go`) compares the length of that text with the same constant. A raw bundle between about 12 and 16 MiB passes the CLI and is refused by the server.

## Decision

Proposed: the server decodes the bundle before checking it, so both sides bound the raw size, and a test sends a bundle just under the limit.

## Consequences

A bundle the CLI accepts is one the server accepts. The request body cap (DL-005) still bounds the encoded form.
