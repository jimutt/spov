## Context

DL-099 made the README a first-time user's page, and its Get started section is five numbered steps with a hand-written YAML block. With `spov init` (DL-123, DL-124) most of that is one command. The errors a newcomer meets first (no platform configured, no Modal credentials, an unpublished image) each name their own fix and none names init.

## Decision

- **The README's Get started** becomes three steps: install, `spov init`, `spov fly`. The "You need" list stays, since init cannot make accounts. What init does is described in a short list (Modal, GitHub through gh, a model, the image), and the manual commands move to a "By hand" subsection that keeps today's content for people who script their setup or use another forge. The install script's closing lines name `spov init` as the next command.
- **`docs/sessions.md`** gains a short "First-time setup" section on init, `--check` and `--json`, and `docs/credentials.md` says init sets up GitHub through gh.
- **First-run hints.** Three errors gain one closing line that names `spov init`, each only when a local server is in use:
  - no git platform configured (`resolveRepoRefs` and the picker);
  - no Modal credentials (`credentials.ResolveModal`'s error, where the CLI reports it);
  - the base image is not published (the launch's "image not published" failure).
  The existing fix stays in each message; init is added after it, never in place of it.
- **`spov` with no arguments** and `spov --help` list `init` first among the commands, with the short text "Check this machine is ready, and set up what is missing".
- **The troubleshooting list** in the README ("When something goes wrong") starts with `spov init --check`.

## Rationale

The quickest path should be the one the page leads with, and the manual path must stay findable because init covers only GitHub through gh. Hints are added to the errors a first run actually hits, and kept to three, so init does not become noise in every message.

## Consequences

- `TestEveryNamedCommandExists` checks the new hints name a real command.
- The README's manual steps and init can drift apart; the "By hand" subsection is short and names the same commands init calls.

## Implementation notes

- README.md, docs/sessions.md, docs/credentials.md, scripts/install.sh (its last lines), and the three error sites in `internal/cli`.
- AGENTS.md gets a short "First-time setup" map entry naming `initSteps`, the config writer and the guard tests.
