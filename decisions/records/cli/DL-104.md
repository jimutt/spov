## Context

A session launched from a checkout is synced (DL-027, and since DL-095 the default inside a checkout). When its TUI exits, `spov fly` exports the sandbox's repository state, applies it to the checkout, and only then terminates the sandbox (`syncSessionBack` before `terminateSession`). `spov resume` (DL-090) reopens a stopped session and attaches the same way, but on exit it terminates the session without syncing. The work survives only in the next exit snapshot, not in the checkout, unless the person remembers `spov stop <name> --sync`. With sync the default, most resumed sessions are synced ones. Decided with the user on 2026-11-07.

## Decision

This amends DL-090's "exiting the TUI stops the session again unless `--keep`" for a synced session, and DL-027's switches, which gain `spov resume`.

### On exit

When the TUI of a resumed session exits, without `--keep`:

| The session | `spov resume` was run | What happens |
|---|---|---|
| synced (`SessionView.sync` is set) | inside a checkout of its repository | the state is exported and applied to the checkout with `git.ApplySync` (in place, or on `spov/<session>` when the checkout has moved on), then the session is terminated |
| synced | anywhere else | the session is **left running**, and spov prints `spov stop <name> --sync` (to run in the checkout), `spov attach <name> --sync`, and `spov stop <name>` to discard. It bills until one of those, or its idle timeout. |
| not synced | anywhere | terminated, as today |

A sync that fails leaves the session running and prints the same retry hints `fly` prints (`printSyncFailureHint`), so the sandbox is never terminated over unapplied work. This is DL-027's sync-before-terminate rule.

"Inside a checkout of its repository" is `verifySyncCheckout`: the working directory's checkout has the session's repository as its remote, on the session's platform, or is the local-only repository by name. It is checked once, when `spov resume` starts, so the person knows before the TUI opens.
- Outside the checkout, a note says the session will keep running on exit and how to sync it.
- The same check decides whether the resume sends the base commit for a transcript resume (DL-098).

Unlike a launch, a resume has no clean-checkout precondition. The export lands on the fallback branch whenever the checkout has moved on, so a dirty or moved checkout is safe.

### The switches

- **`--no-sync`** terminates on exit without syncing, as `spov resume` does today. The work stays in the next exit snapshot.
- **`--sync`** asks for the default explicitly. It is refused before anything starts on a session that is not synced, or when the working directory is not its checkout. That way a script that wants the work back fails fast rather than leaving a session running.
- The two are mutually exclusive.
- **`--keep`** leaves the session running on exit and syncs nothing, as for `fly`. The hints it prints name `--sync` for a synced session (`printAttachHintMode` with sync on).
- **`--no-attach`** and **`--json`** resume without attaching, so they never sync. The hints name `--sync` as `--keep`'s do.
- `spov attach` on a stopped session, which offers to resume it (DL-090), keeps attach's rules: attaching never terminates, and syncs only with `--sync`.

## Rationale

- A resumed synced session is the same session `fly` started. Its work should come back the way it did the first time, without a second command.
- Leaving it running outside the checkout is the only choice that neither loses the work from the checkout nor writes it somewhere wrong. The hints make the next step one command, and the idle timeout bounds the cost.
- `--sync` failing fast gives scripts a way to insist on the round trip.

## Consequences

- A synced session resumed from another directory keeps billing after its TUI exits, until it is synced, stopped or idles out. The note at start and the hints at exit say so.
- `spov resume` gains `--sync` and `--no-sync`. `TestEveryNamedCommandExists` covers the hints that name them.

## Implementation notes

- **`internal/cli/resume.go`.**
  - `resumeOptions` gains `Sync`, `NoSync`, and the cobra flags with `MarkFlagsMutuallyExclusive("sync", "no-sync")`.
  - In `runResume`, after `GetSession` and before `c.Resume`:
    1. compute `synced := view.Sync != nil && !opts.NoSync`;
    2. if synced, `checkout, cerr := env.verifySyncCheckout(ctx, cfg, view)`;
    3. with `opts.Sync`, refuse when `view.Sync == nil` ("session X was not started from a checkout") or `cerr != nil`;
    4. when synced and `cerr != nil`, print the note to stderr ("not in a checkout of owner/name: leaving the TUI will keep the session running; spov stop X --sync from the checkout brings its work back").
  - `resumeSeed` (DL-098) calls `verifySyncCheckout` too. Compute it once and pass the result, so the two can never disagree.
- **The exit path.** After `handOver` returns, without `--keep`:
  1. when `synced && cerr == nil`, call `env.syncSessionBack(ctx, c, cfg, sess.View)`;
  2. on error, `printSyncFailureHint(env, name)`, then `detach(env, sess)`, and return the error;
  3. otherwise `terminateSession`;
  4. when `synced && cerr != nil`, call `printAttachHintMode(env, name, true)` and `detach(env, sess)` instead of terminating.

  `syncSessionBack` re-checks the checkout and runs under `context.WithoutCancel` with `syncTimeout`, as for `fly`, so the Ctrl-C that closed the TUI does not abort it.
- **The other exits.** Make the `--keep`, `--no-attach` and error paths' `printAttachHintMode(env, name, false)` calls pass `synced`.
- **`docs/sessions.md`** ("Resuming a stopped session"): say that a synced session syncs back on exit when resumed in its checkout and stays running elsewhere, and add the two flags. The README's resume line needs no change.
- **Tests to add** (in `internal/cli`, with the in-process API, a persistent fixture and a git checkout, as `TestFlySyncSeedsAndSyncsBackBeforeTerminating` cans the sandbox's export):
  - `TestResumingASyncedSessionSyncsItBackOnExit`: the checkout gets the canned commit and file, and the session is stopped.
  - `TestResumingASyncedSessionElsewhereKeepsItRunning`: the session is still running, and the hints are printed.
  - `TestResumeNoSyncTerminatesWithoutSyncing`.
  - `TestResumeSyncIsRefusedOutsideTheCheckoutAndOnAnUnsyncedSession`: nothing is resumed.
  - `TestAFailedSyncOnResumeLeavesTheSessionRunning`.
  - `TestResumingAnUnsyncedSessionTerminatesAsBefore`.
