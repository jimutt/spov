## Context

The CLI already accepts a mode in `--model provider/model#mode`, which few people would guess. DL-187 checks a launch's own mode at create and answers with the modes on offer.

## Decision

- `spov fly` and `spov jobs create` take `--reasoning <mode>`. With `--model`, it is that model's mode; without, it is the mode of the model the launch resolves to, so the CLI sends the server a mode with no model only as `reasoning`, a field of its own the server applies after `resolveModel`. `--reasoning` with a `--model` that already names a `#mode` is refused before the server is asked. `--reasoning default` sends no mode.
- The server's 422 from DL-187 is printed as it comes, so a wrong mode lists the right ones. Completion of `--reasoning` offers the modes of the `--model` given, read from `GET /api/v1/models` through `Env.existingClient` (never starting a server), and nothing otherwise.
- The flag joins `TestEveryNamedCommandExists`'s known flags, and the docs name it where they name `--model`.

## Rationale

A flag of its own is discoverable in `--help` and completion, and a separate field lets a user set a mode on their default model without retyping it.

## Consequences

- The session and job create requests gain an optional `reasoning` field, generated into the web client like any other; the web forms keep sending `#mode` in the model field (DL-189).
