## Context

When `spov fly` is given no `--repo` and the project file names no repositories, the user chooses from a picker (DL-023). With several platforms configured, refusing and asking for `--repo <platform>:owner/name` puts a prompt for typing a qualified name in a tool that has a picker, in exactly the configuration where typing it is most tedious. And with two accounts the list is the sum of both, so scrolling to a repository is impractical without search.

A general-purpose form library's multi-select filters by a hardcoded case-insensitive substring match, reached only after pressing `/`, and exposes no hook to override its filter function. Substring matching means `spv` does not find `spov`, and `adf` does not find `acme/dotfiles`, which is why the picker is spov's own model.

## Decision

### One merged list

With several platforms configured and nothing named, the picker shows one list of every platform's repositories, each row labelled by its platform. A selection may span platforms. The listing is the server's (`GET /api/v1/repos`, DL-002); the CLI holds `RepoChoice{Platform, Repo}` and no platform clients.

- Platforms are listed concurrently, so the wait is that of the slowest platform, not the sum.
- A platform that fails to list is a warning naming the platform and why, carried in the response and printed by the CLI after the view closes. Only if every platform fails does the command fail, and then it reports each error. Tokens for different platforms expire independently, and an expired token for one forge must not block a launch that only needed repositories on another.
- When the list holds repositories of one platform only, whether one is configured or only one answered, the picker shows no platform column and matches the slug alone (`slugColumnWidth`, `pickerHaystack`).
- Two platforms that expose the same `owner/name` are distinct rows, told apart by the platform column.
- Each row ends with a detail that helps pick and is not searched: `private`, `archived`, a note on a public repository that the token may only read, and how long ago it was updated.
- Rows are in the server's order, most recently updated first.
- On a hosted server each platform is read through each credential tier the caller has, and the listing marks which tiers reach each repository (DL-042). The CLI's picker drops a repository the tier its launch resolves to cannot reach (`reachableFromHere`) and prints a note per platform saying how many were left out and which `prefer` setting would reach them. A listing with no tiers, from a local server, keeps everything.
- `--repo <platform>:owner/name` stays as the way a script names a repository exactly, and a bare `--repo owner/name` with several platforms configured is ambiguous and refused.

The picker is offered only when `/dev/tty` can be opened (DL-023); otherwise `fly` says to pass `--repo`.

### spov's own model

The picker is a `tea.Model` owned by spov, in `internal/cli`. It draws a title, a query line with a match count, the scrollable rows (at most 15 visible, fewer on a short terminal) with a checkbox per row, and a help line. Because it is a pure model, key sequences are driven in unit tests without a terminal.

Interaction:

- **Typing filters at once.** Printable characters extend the query. There is no `/` and no mode. Backspace deletes a rune and Ctrl-U clears the query.
- **Selection is by identity.** A repository is selected by its index in the full row list, never its position in the filtered view, so filtering and reordering cannot change what is selected. A repository selected under one query stays selected when the query changes. The confirmed result is every selected repository, in the order offered, and not only those matching the final query.
- **Space always toggles** the row under the cursor and never reaches the query. The terminal decoder emits the space bar as `{Code: KeySpace, Text: " "}`, the same as any printable character, so a typed space and a select press are one event. Nothing is lost: a slug has no space, and the platform can be searched by typing its name alone. A test built on a bare `{Code: KeySpace}` passes while real terminals break, so tests use the message the decoder produces (`TestPickerSpaceSelects`).
- **A modifier other than shift is a command, not input.** `alt+x` carries printable text and does not reach the query.
- Up, Down, Ctrl-P, Ctrl-N, PgUp and PgDn move the cursor. Enter confirms and is refused inside the picker, with a message, when nothing is selected. Esc and Ctrl-C cancel with an error the caller handles.
- Every line of the view, titles and help included, is truncated to the terminal width, because a wrapped line pushes the rest of the view down.
- The picker draws on stderr, so stdout carries only the command's own output, as `--json` needs (DL-023).

### Fuzzy ranking over the visible row

Matching uses `github.com/sahilm/fuzzy`, which `bubbles/list` also uses: case-insensitive, over the row's text, `owner/name` first and then the platform name joined by one space. With a platform column, typing a platform name therefore narrows to that platform. A query cannot contain a space, because space toggles.

- **The slug comes first.** The matcher is greedy, not optimal. With the platform leading, a query such as `docs` is spent on letters inside the platform name, and a repository actually named `spov-docs` scores far below the same repository on another platform.
- **Weak matches are dropped** when they score more than `maxScoreGap` (12) below the best match for the same query. Subsequence matching alone is too permissive on a long list: `dot` matches `alice/java-demos` by taking one letter from each of three words. The cut is relative to the best score and not an absolute floor, because scores are not comparable between queries and a good match can be negative.
- **Order:** by score when there is a query; the natural order (most recently updated first) when there is none; ties by natural position, so rows never swap while typing.
- **What is matched is not what is drawn.** The haystack is the slug, one space and the platform name. The padding that aligns the platform column is added only when rendering, because the scorer penalises the distance between matched characters, and padding inside the haystack made a row with a wide column outrank a better match. The library returns byte offsets into the haystack, and `pickerRow.shift` moves them past the inserted padding before the matched characters are highlighted.
- A query that matches nothing shows an explicit empty state, since a blank list looks like a broken picker.

## Rationale

- Offering everything leaves nothing to guess, and the platform column is the only new information a merged list needs.
- Warning instead of failing matches how spov treats partial credential problems elsewhere, and the failure it guards against is common.
- Owning the picker is the only way to get type-to-search with fuzzy ranking. Pre-filtering in a separate prompt would make refining a query a two-step round trip, and forking a form library to patch an unexported function would pin a patched dependency.
- Index-based selection in a filtered list silently selects the wrong repository once the list reorders. Identity makes reordering harmless by construction.
- Matching the visible row makes the platform column searchable. A column that can be seen and not searched is a surprise, and narrowing to one platform is what someone with two accounts wants.
- Stable ties matter: an unstable sort makes rows swap places while typing, and that is what makes a fuzzy list feel unusable.
- `sahilm/fuzzy` is small, has no transitive dependencies and is used by one function. Ranking changes if it is upgraded, so tests pin only what spov depends on: a subsequence match is found, a better match ranks first, and equal scores keep their natural order.

## Measurements

- Relative score gap: 12. A good match can score -12 (`irb` against `acme/irrbloss`), while noise for another query sat 37 below its best.
- Greedy-matcher trap: with the platform leading the haystack, `docs` scored -27 for `spov-docs` on one platform and 50 on another, because the platform name held the letters. Putting the slug first removes the trap.
- Padding trap: with columns padded inside the haystack, `spv` ranked `acme/spov-docs` above `acme/spov`.

These are properties of the library at the version in `go.mod`. `go test ./internal/cli/ -run Picker` re-checks the ranking and the offset mapping.

## Consequences

- `SelectRepos` takes repositories carrying their platform, so rows can be labelled and a selection mapped back to the platform that owns it. The hook is one function over a flat list.
- The interactive path can contact several forges, so it is slower with several platforms configured, bounded by the slowest.
- Reversing the haystack's order degrades matching for any query whose characters also appear in the platform name, and a test guards it. Changing the row format changes what is searchable. An unshifted match offset highlights the wrong characters, and a test covers the mapping.
- The picker owns its keymap and layout, including its behaviour on resize and on lists longer than the window.

## Known gaps

- The relative score gap is a heuristic tuned on real repository names. It can hide a legitimate match that scores far below a better one for the same query. Showing every subsequence match was what made the list unusable.
- A query cannot contain a space, so the slug and the platform cannot be searched as two words. Either alone narrows the list.
