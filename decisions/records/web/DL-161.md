## Context

DL-160 serves each model's reasoning modes for a session and lets the model switch take one. The reader chooses a model in the composer's model control (`ModelSwitch.svelte`, folded behind the model chip on a phone, DL-117).

## Decision

- Beside the model in a running session's composer there is a Reasoning choice: Default, then the selected model's modes in OpenCode's order and words, read from `GET /sessions/{ref}/model-variants` when the composer first shows and again when the session's sandbox changes. The session page does the reading (`SessionDetail`'s `readVariants`, once per sandbox of a running session) and hands the list to the composer, so a composer drawn again, as after a subagent view (DL-113), asks for nothing. While nothing is read for the sandbox it is asked again every `VariantsRetryMs` (15 s), at most `VariantsRetries` (8) times, and when the reader opens the model control. It is drawn only when the selected model has modes; otherwise, and while the list is not read, nothing is drawn.
- Choosing a mode switches at once through the same `POST /sessions/{ref}/model` the model choice uses, with `provider/model#mode`; Default sends the reference without one.
- Choosing another model keeps the current mode when the new model offers a mode of the same id, else goes back to Default (`switchedTo` in `web/src/lib/reasoning.ts`).
- The current mode is read from the log's `session.model.selected` as the model is (`currentModel`), and the model chip names it after the model (`model · high`, `modelChip`). Default names nothing.
- On a phone the choice sits in the composer's folded options with the model control, as one more grid cell, never a second copy. It is not offered on `/sessions/new`, `/jobs/new` or Settings, which have no sandbox to ask.

## Rationale

The reader picks a mode the way they pick a model, in the same place, and only ever from what the model accepts in this sandbox. Keeping a mode across a switch when the new model has it is what a reader who chose "high" expects; falling back to Default otherwise never sends a mode the model lacks.

## Consequences

- A model with no modes shows no Reasoning choice at all, rather than a lone Default.
- A refusal of the switch (the list changed under the page) is shown like any other switch failure, and the page re-reads the list (`ModelSwitch`'s `onStale`).
