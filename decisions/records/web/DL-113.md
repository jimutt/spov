## Context

OpenCode lets a reader enter a subagent's session from its task row and move around the tree: down into a child, left and right between siblings, up to the parent. The page spov draws is one transcript for one spov session (DL-057), with a sidebar, and the card of DL-112 shows a child inline. A long subagent run (the review that surfaced this problem ran nine messages and many tool calls) is more than a card should hold, and an operator debugging a job wants the child's whole transcript, with its tool lines and its text, at full width.

The page also has write controls (composer, Interrupt, Resume, End, Cancel; DL-059, DL-057). None of them can be pointed at a subagent: the send names no conversation, the server routes an unnamed one to the person's own (DL-109, DL-110), and Interrupt asks only whether some turn is running.

## Decision

### A view, not a route

The session page takes an optional `agent=<OpenCode session id>` beside `id` (`/session/?id=<ref>&agent=ses_…`), so a subagent is a link a person can share or reload, and there is still no job route and no second page (DL-057, DL-061). The id is read from the query string at load and on navigation, and the view is drawn from the conversations and log the page already holds.

With `agent` set the page draws:

- the **child's timeline** (DL-111's per-conversation list) in the same column and with the same blocks as the main one, including its prompt row, with the card's state and label as a heading;
- a **breadcrumb** above it: `<session> › <subagent label>`, whose first part returns to the main transcript (a child under a child adds its ancestors, each a link, and a phone shows one level up as "…"), and "Previous"/"Next" with "n of m" between the siblings of the same parent, in creation order, for a parent with several;
- **no composer, no Interrupt, no Resume**; in their place one quiet line: "You are reading a subagent. Messages go to the main conversation," linking to it. The sidebar's session facts and the job's state stay as they are, because they are the session's.

An `agent` id that names no subagent the page holds draws the main transcript with a one-line note, never an error page; the note waits until the conversations are read, so a direct link never flashes it. A child still being recorded follows the same live log as the main view. A question a subagent raised stays in the main list (DL-020), so its view says "N waiting on you, in the main conversation" with a link, rather than drawing a second copy of an ask.

A card gains an "Open" link to the view. A plain click is taken over (`history.pushState`; Back and Forward are read from `popstate`), nothing is requested and the log is not reopened; a modified click is the browser's, so a view opens in a new tab as any link does.

### The sidebar lists them

The sidebar gains a "Subagents" list, shown only when the session has children: each child's label, state mark and (from the card's counts) its call count, nested one level under its parent where children have children (OpenCode allows `subagent_depth` above 1), each linking to its view. It is a list of facts, as the rest of the sidebar is, with no explanation behind an (i).

A long session can run dozens of subagents, so the list lists only what is live and puts the rest away (`sidebarList` in `subagentview.ts`):

- a subagent is **live** when it is starting or running, or when it or one under it has a question waiting on the reader. Live ones are always listed, in tree order;
- the subagent whose **view is open** is listed too, finished or not, and every ancestor of a listed subagent is kept so the nesting reads, so a finished parent of a running child stays in the live part;
- every other subagent is **finished** (done, failed or stopped). They sit behind one disclosure, closed by default and drawn like the Sandbox section's, whose summary reads "18 finished", and open as a flat list, most recently created first. A subagent is never listed both above and inside it;
- the section's heading carries the counts by state, only the non-zero ones, in the card's words: "Subagents · 2 running, 18 done, 1 failed, 1 stopped". With nothing live, the live part is empty and the heading and the closed disclosure are all that show.

The list is still the one sidebar element, so the phone sheet holds the same list and a link inside the disclosure closes the sheet as the others do (DL-106).

### Not in the session lists

The sessions list and the CLI list sessions, never conversations, so nothing changes there. The only place a child's text could reach a list is the row's last-message preview, which DL-115 fixes.

## Rationale

- A view on the existing page, selected by a query parameter, reuses the page's live log, tail latch, window and markup and adds no route, which is the shape the rest of the web app takes for the same reasons (DL-057, DL-061).
- Read-only is the honest state: spov has no way to steer a subagent and DL-109 keeps it that way. A composer that appeared and sent to the main conversation would be the same misattribution the plan removes, in the other direction.
- Breadcrumb, siblings and a back link are OpenCode's `session.parent` and `session.child.*` in a form a browser reaches without a keybinding; the sidebar list is OpenCode's subagent picker.

## Consequences

- `SessionDetail.svelte` is already large; the child view's heading and breadcrumb are a component (`SubagentBar.svelte`) and the tree is `subagentTree` in `subagentview.ts`, read from the cards `buildTimelines` already drew, so the labels and states are the card's and creation order is the order of the calls. It has its own tests; the component test asserts markup state (no composer, the breadcrumb's links), as AGENTS.md prescribes, since jsdom has no layout. A child with nothing recorded yet has no card, so it is not in the tree and its id reads as unknown until a frame or message arrives.
- The phone layout (DL-106) needs the breadcrumb at 390 px: it truncates the label and keeps the back link. It is looked at in a browser at the three widths before the change merges.
- Tail and window behaviour: switching view resets the tail latch and the window (DL-070), so a view opens at its newest blocks as a page just opened does, and does not reopen the log.
- The task prompt row is `SubagentPrompt.svelte`, drawn alike inside a card and in the view.
- This is the last step of the plan. DL-111 and DL-112 fix the misattribution and show the work; this one adds depth, and the earlier steps stand without it.
