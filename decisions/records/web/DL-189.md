## Context

DL-161 offers a reasoning choice only in a running session's composer, because the forms had no sandbox to ask. DL-187 serves each model's modes in `GET /api/v1/models`, which `/jobs/new`, `/sessions/new` and Settings already read for their model pickers.

## Decision

- `/jobs/new`, `/sessions/new` and the Settings default model draw a Reasoning choice beside the model picker: Default, then the chosen model's modes from the models response's `variants`, in OpenCode's order and words. It is drawn only when a model is chosen in the form and that model has modes; with the form's first option (the inherited default, `defaultOptionLabel`) nothing is drawn, since that default carries its own mode from Settings.
- The form sends the model as `provider/model#mode`, or the bare reference for Default. Choosing another model keeps the mode when the new model offers a mode of the same id, else returns to Default (`keptMode` in `web/src/lib/reasoning.ts`, the composer's `switchedTo` rule before a sandbox exists).
- Settings seeds the choice from the stored default's `#mode`: the field still holds the whole `provider/model#mode`, and its model picker and Reasoning choice are bound to its two halves (Svelte function bindings), so `seedField`'s rule of returning its argument unchanged holds; an empty model clears the mode with it. Choosing the same model again, or any model before the list is read, keeps the stored mode (`chosenModel`), and a mode change clears a saved note or refusal as a model change does (`reconsider`). `PATCH /me` checks a default's mode against the modes offered (DL-187).
- A held mode the read list does not offer is drawn after the offered ones as a disabled "<mode> (not offered)", selected, as DL-161 draws it; only Settings adds a note (a launch on the default runs on the model's own default, DL-188), since a form's own mode is refused at create. Before the list is read a held mode is drawn as an ordinary option, unjudged (`known`).
- `toJobRequest` (the draft's `mode`) and `toSessionRequest` set the mode through `withModeOf`, built on `withoutVariant`, so one parser of a reference remains: first `#`, an empty half is no mode.
- On a phone the choice is one more cell of the form's grid, never a second copy (DL-106).

## Rationale

The choice sits where the model is chosen and reads the same list the server checks, so what is offered is what a create accepts. Leaving the inherited default without a choice keeps one place, Settings, where that default's mode is set.

## Consequences

- The Settings page's model field can now hold a mode, and every launch that inherits the default uses it, subject to DL-188 at the opening.
