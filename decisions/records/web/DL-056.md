## Context

spov is read for its identifiers (job IDs, sandbox IDs, device codes, model references, commit hashes) and for the state of work that runs while nobody watches. The app's look follows from that. A face where `0` and `O`, and `1`, `l` and `I`, differ matters more than a fashionable one. State has to be readable without colour. The one warning that matters, cost, must not look like the rest of the page.

A serif on a warm ground makes a transcript read as a chat rather than as a log of work. A monospace used for dates, prices, states and buttons as well as for IDs stops telling the reader which text is literal. Small tracked capitals as the page's main way of showing structure are hard to read. A colour that means five things means none of them. This record fixes the rules that avoid those.

## Decision

### Type

One sans carries everything people read and one mono carries text you could paste into a terminal.

- The interface and the transcript use Atkinson Hyperlegible Next. Machine text uses Atkinson Hyperlegible Mono: IDs, repositories, paths, commands, model references, event names and credential names. Dates, durations, prices, states, kinds, buttons, labels and the signed-in address use the sans, with tabular figures where numbers line up in a column.
- There is no serif anywhere, including agent prose and the report preview. Hierarchy comes from size, weight and colour. Nothing is set in capitals or tracked out to mark structure.
- The scale is six steps, defined once in `global.css`: 13, 14, 15, 16, 20 and 24 px as `text-sm`, `text-md`, `text-base`, `text-read`, `text-lg` and `text-xl`. UI text is 15 px. Transcript text is 16 px at a line height of 1.6. Nothing is under 13 px except `<kbd>` at 12 px (`text-xs`). Weights are 400, 500, 600 and 700, all from one variable file per style. Spacing uses Tailwind's 4 px steps.
- The slashed zero that both faces draw, including in a time such as 14:02, is accepted as the cost of telling `0` from `O` in an ID.
- The `.md-body` rules set rendered headings in the sans and code in the mono, so a message or a report preview uses the same two faces as the page (DL-063).

The faces are bundled, so the page makes no third-party request. They come from the Fontsource variable packages `@fontsource-variable/atkinson-hyperlegible-next` and `@fontsource-variable/atkinson-hyperlegible-mono`, pinned exactly at 5.3.0 (Google Fonts' own builds under the SIL Open Font License 1.1). `Base.astro` imports their CSS; Vite emits content-hashed WOFF2 files into `dist/_astro/`, and `internal/webui` embeds and serves them with the immutable cache header (DL-055). Only what the design uses is imported: Next in normal and italic and Mono in normal, each in the `latin` and `latin-ext` subsets, which is six files. `unicode-range` makes a browser fetch `latin-ext` only for a page that uses one of its characters. Each font stack ends in a system face, so the page renders in a fallback if a file fails to load. A bump is `bun add --exact` of both packages, which also changes the cached asset names.

The licence travels with the files. The OFL asks for it to accompany every copy, and the Google builds keep only the copyright in their name tables. The packages' `LICENSE` texts are copied to `web/public/licenses/` and every page links them with `<link rel="license">`. `styles/fonts.test.ts` fails if a package's licence and its copy differ. The copies are plain files because linking a dependency's extensionless file through a Vite `?url` import builds but cannot be resolved by `astro dev`. `.woff2` is served by `http.ServeFileFS`, which reads the type from the file's own `wOF2` signature, and the response's CSP sets no `default-src` or `font-src`, so fonts need no policy entry.

### Colour

The light theme is a cool stone ground (a paper, a raised surface for controls and the header, a sunk surface for tracks and code, and two rule colours). The dark theme is a cool near-black. Both come from one token set defined once in `global.css` as plain custom properties and swapped wholesale per theme, so a colour cannot exist in only one theme. `@theme inline` re-exports them as Tailwind utilities that follow a runtime theme change.

Every text colour passes WCAG AA, 4.5:1, on both the paper and the raised surface in both themes: `--ink`, `--soft`, `--faint`, `--olive-b`, `--rust`, `--gold-t` and `--stone`, plus `--on-accent` on filled buttons. `--faint` stays quieter than `--soft`. `theme.test.ts` asserts the light block as well as the dark, because a test that read only the dark block let a light failure go unnoticed.

Each colour has one job:

| Colour | Means |
|---|---|
| olive | running or passed; the primary button (filled `--olive-b`, text in `--on-accent`); what is selected (current nav item, active filter, chosen kind and repositories, live ticks of the quota meter) |
| rust | failure and spend |
| gold | what waits on a person or a clock: starting, queued, steered, blocked, a time limit close to running out |
| stone | stopped and unverified |

`--gold` is for marks and track fills only. Gold used as text is `--gold-t`, the same hue darkened (in the dark theme the two are equal). `--ink` is the same in the favicon's copy and the stylesheet. There are no filled tinted chips and no side stripes anywhere: a stripe on agent messages, a coloured chip and a coloured border each carried meaning by colour alone.

Text is not drawn in `--faint` or `--rust` on the sunk surface, where they fall just under 4.5:1.

### States

A state is drawn by one component, `StateMark.svelte`, as a shape, a colour and a word, so it never rests on colour alone.

- Six marks: a filled dot for running (olive), a ring for waiting (gold), a tick for done (olive), a gold tick, `part`, for a success that delivered part of what was asked, a diamond for failed (rust) and a ring for stopped (stone). The marks do not animate; a live state shows by what it says.
- `sessionMark`, `jobMark` and `gateMark` in `format.ts` map session states, job states and gate outcomes onto the marks, on top of `tone`, `jobTone` and `gateTone`, which keep deciding which family a state belongs to (DL-057, DL-050). The mark adds only the tick for `succeeded` and `passed`.
- The word is the state in sentence case ("Steered", "Unverified"). An unknown state still renders, as stopped.
- A partial success is the `succeeded` state drawn with the `part` mark and the words "Succeeded, partly" (`jobMark` and `jobWord` with the job's `partial`). It is wording and a mark, not a state: no filter, count or lifecycle step changes. The folded verdict's "Partial" uses the same mark. A reader scanning a list for what needs a second look should not have to open every success to find the partial ones.

### Controls

- Buttons come in three kinds, defined once in `components/ui.ts`. Primary is filled olive and means the action the view is for, at most one per form or section. Secondary is raised with a `--rule-2` border. Danger is secondary in rust text, and the confirming second press of `ConfirmAct` is filled rust. All are sentence case, 14 px, weight 500, with a 4 px radius. Two sizes differ: Start job, the button that spends, is 15 px (`primaryLarge`), and the floating Jump to latest is 13 px (`secondarySmall`).
- Rounded means you can press it. Controls (buttons, inputs, selects, kind cards, filters) have a 4 px radius (`rounded-ctl`) and containers stay square. Inputs share one field style, a `--rule-2` border on `--raised`, and are set in mono only where the value is machine text: the check command, the repository filter, the credential platform and token.
- Headings are sentence-case names at 15 px semibold ("Workspace", "Cost so far", "Pull request job"), and form labels are 15 px semibold. Speakers in the transcript and the list are words in the soft colour ("Agent", "You", "spov"). Capitals and letter-spacing never mark structure.
- `Problem` is a rust-tinted square box with a rust border, the title in semibold and the detail beneath, with `role="alert"`. A confirmation is plain soft text after an olive tick, with `role="status"` where it has one.
- Icons are a handful of inline SVGs in `Icon.svelte` (chevrons, external link, cross, sun, moon, info) at a 1.5 to 2 px stroke, with no icon library and no emoji. The arrow `↗` appears only as the icon on a link that opens a new tab. The theme toggle is two icon buttons with `aria-label`, `title` and `aria-pressed` (DL-055 describes its three-state behaviour). Key hints use `<kbd>`. The wordmark is "spov" in the sans at weight 700.

### Copy

Seven rules apply to every string in the UI:

1. Headings are names with no closing full stop: Sessions, Jobs, New job, Settings, Tokens, Usage. The signed-out page keeps an instruction: "Sign in to see your sessions".
2. No spaced em dashes in UI strings; a full stop, comma, colon or brackets do the job ("Your default (anthropic/claude-sonnet-4-5)", "No default: OpenCode chooses"). Document titles such as "Sessions — spov" keep theirs, since a tab title is a convention of its own.
3. No middle-dot meta strings. Separate elements are set apart by space or columns, or joined by a comma.
4. No bold inside running text and no sentences about the page itself. Bold is for data: "Works unattended for up to **1 hour** on **acme/app**. Its sandbox is billed for as long as it runs, which can be longer." The second sentence keeps the time limit from reading as a ceiling on billing.
5. Help is one sentence under the field. A longer explanation goes in a `<details>` disclosure named for its question ("What every repository allows", "How the check is run", "How the time limit counts"), so the sentences that record a decision stay one click away, in the DOM and found by in-page search. This applies on `/jobs/new` and `/settings`.
6. A button is a verb and an object where the verb alone is unclear: Start job, Interrupt turn, Resume job, Cancel job, End session, Open pull request #482.
7. Kinds and gates get display names: `pr` is shown as "Pull request" and `check` as "Check". The API values do not change.

Copy that other records pin is kept: the composer's note on a job and the model select's first option label (DL-059, DL-061), the separate wording of the two model refusals, and cost always saying "at least" in words (DL-055). A new sentence of the form "spov <word>" must use a word in `proseWords` or name a real command (`TestEveryNamedCommandExists`).

### The logo

The logo is one path with `fill-rule="evenodd"`, and its interior detail is holes. The two enclosed subpaths are appended to the outline in a single `d`, so the interior is transparent and the mark works on any background. The source artwork has the interior as white shapes drawn on top of the outline. Deleting those shapes would leave a solid blob, and keeping them as white fills gives a logo that looks right only on a white page.

It is drawn in `currentColor`, so it inherits the theme's `--ink` and cannot fall out of step with the palette. The mark is monochrome: the artwork's teal is within 1.4:1 contrast of the dark ground and would read as a smudge, and a second colour for one theme would break the rule that the palette is defined once. The geometry lives in `logo.ts` (`MarkPath`) and `Logo.svelte` renders it for the header, the 404 page and empty states. The component hides the mark from assistive technology with `aria-hidden` alone, since a `role="presentation"` next to a global attribute is ignored, unless it is given a name. The `preserveAspectRatio="none"` and the width and height of the artwork are dropped, so the box follows the mark.

`web/public/favicon.svg` is a second copy of the path, kept by hand: a favicon is fetched outside the page and cannot inherit `currentColor`, so it carries its own two colours and switches them with `prefers-color-scheme` inside the SVG. `logo.test.ts` asserts that the favicon's geometry equals the component's and that its two colour literals equal the stylesheet's own `--ink` values, read from `global.css` itself, because a copy checked against another copy passes while both drift from the original. Reading the stylesheet in vitest needs `css: true` in `vitest.config.ts` (the default `css: false` empties it), and test files cannot import `node:fs`, because the project has no `@types/node` and `astro check` fails on it; they use `import.meta.glob(..., { query: '?raw' })`.

## Rationale

- A face drawn so that `0`/`O` and `1`/`l`/`I` differ helps with exactly what spov shows. Atkinson Hyperlegible is free, has a sans and a mono drawn to go together, and is distinctive rather than the default of most developer tools. IBM Plex and Recursive were the alternatives; Atkinson was preferred for the legibility of identifiers.
- Mono keeps one meaning only if it is used for one thing.
- Bundling puts the faces on the same origin as the page and removes the third-party request. They are small (measured below).
- Giving each colour one meaning lets the reader learn it: olive then means "running, passed, or the button to press" and nothing else. The darker secondary tokens are the smallest change that makes every text colour pass AA on the surfaces it is drawn on.
- A state drawn by colour alone fails anyone who cannot tell olive from gold. A shape and a word make it readable without colour, and one component makes it look the same on every page.
- Three button kinds let a view say which action it is for, and "one primary per view" is what gives primary a meaning. Giving the radius a meaning means the shape tells you what you can press.
- Size, weight and colour show structure as well as tracked capitals did, and read faster.
- Holes rather than white shapes are what "transparent" means for this mark. `currentColor` needs no dark-mode variant, second file or media query in the component. One geometry module means the mark is corrected in one place.

## Measurements

- **Bundling the faces.** Six font files are 139,356 bytes and the two licence texts 9,208 bytes. Together they add 154,580 bytes to `internal/webui/dist` (558,047 against 403,467 without them, including that change's own CSS and script) and 155,664 to the `spov` binary (79,452,890 against 79,297,226, about 0.2%). The latin files a typical page fetches are 51,748 bytes (sans and mono upright). Re-run: `scripts/build-web.sh`, then `go build ./cmd/spov`.
- **Layout width.** The sidebar is 280 px wide, not the 268 px a narrower face allowed, because Atkinson sets wider.
- **Contrast.** Without the palette rules: light `--faint` was 2.93:1 on the paper and 3.23:1 on raised, gold text was 3.63:1, and dark `--stone` was 4.41:1 on raised. With them: every text colour is at or above 4.5:1 in both themes, and `--gold` on the paper is 3.62:1, used only for marks and fills (non-text minimum 3:1). Re-run: `cd web && bun run test -- theme.test`.
- **Logo artwork.** All 267 of 267 and 314 of 314 vertices of the two white outlines lie inside the outline, so they are holes. The teal is within 1.4:1 of the dark ground.
- **Stylesheet read under vitest.** With `css: true`, `global.css` reads back in full, with its three `--ink` declarations (3,757 characters when measured); under the default `css: false` it reads back empty. Re-run: `cd web && bun run test -- logo.test`.
- **Capitals and mono without the rules.** About 45 `uppercase` and 50 `tracking-[…]` utilities at about 10 px in the faintest colour, 108 uses of `font-mono`, and about twelve copies of the button class string across seven files.

## Consequences

- A new state lands in the family `tone`, `jobTone` and `gateTone` choose, and `Mark` is a union, so `StateMark`'s colour table (a `Record<Mark, …>`) fails `astro check` until a new mark is placed.
- Mounted tests select by `data-testid` and role. A test that reads a state word reads it case-insensitively.
- A bump of the font packages must be done for both together, and the licence copies must be refreshed or `fonts.test.ts` fails.
- The favicon holds a second copy of the path, so a change to the mark is two edits, guarded by `logo.test.ts`. An Astro static endpoint could generate the favicon from `MarkPath` and remove the copy and its test, but would put the favicon behind the web toolchain, which a plain `go build` does not run. Revisit if the mark is reworked.
- `--ink` keeps its value in both themes so the favicon's copy stays valid. A change to it changes the favicon and the test together.

## Known gaps

- There is no raster icon. An `apple-touch-icon.png` needs a rasteriser and a build step the project lacks.
- Safari renders an SVG `rel="icon"` only from Safari 26, so older Safari and iOS show no icon; there is no `.ico` or PNG fallback.
- A favicon's `prefers-color-scheme` is evaluated once, when the browser fetches the file, so flipping the system theme does not recolour the tab icon until a reload.
- The logo is monochrome. A two-tone mark that works on both themes would need a palette entry of its own or a per-theme variant.
- Text in `--faint` or `--rust` on the sunk surface falls just under AA, so those pairings must not be drawn.
