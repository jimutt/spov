## Context

The transcript lays the stored messages and the log's events on one list by time (DL-058). A stored message's time is OpenCode's `time.created`, which for the agent's message is when its step opened, before the model reasoned or called a tool. A thought is drawn from `session.reasoning.ended`, dated when it finished. So the reasoning that led to the agent's last message sorted below that message, and a reader of a finished session saw a thought after the answer and had to scroll up to find that the agent was done.

The log also carries the words themselves on `session.text.ended`, dated when they were finished. While the stored message holds the same words, that event is not drawn (DL-058's promotion rule), so its time was unused.

## Decision

- An agent's stored message (`role: assistant`) whose words match a `.text.ended` event of the log is drawn at that event's time and log position, not at its own `time.created`. It keeps its key, so the element does not change.
- Messages with the same words take the matching events in order, one each, and a message is only ever moved later, never earlier.
- A message with no matching event (one read before its event arrived, a log the window has not reached, a recording that stopped) stays at its own time, as before. A person's message and spov's are not moved.

## Rationale

The text event marks where the words were finished, which is where they belong among the step's thoughts and tool calls. Moving the message rather than promoting the event keeps the stored message as the one copy drawn, so the page neither repeats the words nor changes which element holds them when the transcript is read again.

## Consequences

- `timeline.test.ts` checks that a message is drawn after its own step's reasoning and that two messages with the same words each take their own event.
- A message whose stored text differs from the event's (a step with several text parts joined in one message) matches nothing and stays at its own time.
