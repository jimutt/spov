## Context

DL-042 marks a public repository that a launch would reach only through the person's own fine-grained GitHub token (`RepoView.maybe_read_only`), since such a token can read every public repository but pushes only to those it was given. It has the browser's picker draw a note under each marked repository: "Public: your token can read it, and can push only if you gave it this repository" (`repoReadNote`). A fine-grained token lists many public repositories, so the note repeats down the list, and its wording is long for the one line it qualifies.

## Decision

The browser's repository picker draws no note on a marked repository. It is listed and selectable as any other; `repoReadNote` is removed.

- The server keeps sending `maybe_read_only` as DL-042 has it, so a client can still tell the case apart.
- The CLI's picker keeps its short detail, "public, push only if your token was given it" (`repoDetail`), which is a few words on the row it already prints.
- A launch on such a repository that cannot push fails as it always could, at the push, with the forge's refusal, which the generated guide tells the agent to report rather than work around (DL-108).

The note comes back, in a shorter form, only if people turn out to be confused by a push that fails on a public repository they picked in the browser.

## Rationale

The note explains a rare failure on every row of a long list, which makes the picker harder to read for the common case to help the uncommon one. Without it the picker shows what the person can choose; the failure, if it comes, names itself.

## Consequences

- A person picking a public repository their token was not given learns at the push, not in the picker.
- `maybe_read_only` has no reader in the browser for now; it stays in the API for the CLI and for a later note.
