## Context

Agents write Markdown whether or not anyone asked: headings, lists, fenced code and tables. Two places in the web app show it:

- **A report job's report.** A download is a poor way to glance at a short report, so the session page previews it in a modal and keeps the download for keeping and for anything large.
- **The transcript.** Rendered as plain `whitespace-pre-wrap` text, a reply containing a fenced diff is a wall of literal backticks and hashes. Every session has messages, so this is the more common case.

Both inputs are attacker-influenced. A report is written by an agent in a sandbox, and a message is whatever the model emitted, which a prompt-injected agent controls. Svelte's escaping is what protects the page, and rendering Markdown is the act of turning text into markup. It removes that protection by design, so an explicit sanitiser has to replace it.

A report also sometimes needs a picture: a chart, a screenshot or a diagram. A remote image in agent text is a request from the reader's browser to a URL the sandbox chose, which tells that URL who read the report and when.

## Decision

### One renderer, one sanitiser

`web/src/lib/markdown.ts` is the only place the page bypasses Svelte's escaping. It has exactly two `{@html}` sites, both in `SessionDetail.svelte`: a transcript message and the report preview. Both go through `render`, which parses with `marked` and sanitises with DOMPurify.

- Two sanitiser configurations would leave the weaker one for an attacker to find. The two uses differ only in presentation: the caller wraps the output in `md-body` (a report) or `md-body md-message` (a message), and the stylesheet demotes a message's headings. Heading tags are allowed rather than withheld, because withholding them keeps the text but loses the line breaks around it, so `# Done` followed by prose would read as one sentence.
- Raw HTML in the source is not trusted: `marked` passes it through and the sanitiser removes every element and attribute the allowlist does not name. The allowlist is an allowlist, not an exclusion list, and the sanitiser must be an allowlist kind.
- The dialect is GFM with `breaks`, so a single newline is a `<br>`, since agents write line-oriented output such as file lists and stack traces. The `Marked` instance is private to this module.
- `marked` 18.0.11 and `dompurify` 3.4.14 are pinned exactly.
- Structural event rows in the transcript are not rendered as Markdown, since an event name could draw a heading.

### What a rendered document may contain

- **Elements:** `p br hr strong em del code pre blockquote ul ol li a h1`-`h6 table thead tbody tr th td`. `img` is added only in a report preview with an image source (below). `style`, `link`, form controls and embedding elements are not in the list. DOMPurify drops `script`, `style`, `iframe` and `form` with their content.
- **Attributes:** `href title align colspan rowspan`. There is no `id`, because it would collide with the page's anchors and with a label's `for` target, and no `style`, because it can place content over the page's own controls.
- **`class` is admitted by a hook only to be narrowed.** An `afterSanitizeAttributes` hook keeps a class on `code` only when it matches `^language-[\w+#.-]+$`, which is marked's fence label, and removes every other class. Tailwind compiles the classes the app's own source uses, so every utility is reachable by name from rendered content. `class` is put in `ADD_ATTR` because the allowlist runs before the hook, so the hook cannot keep what the allowlist removed.
- **`ALLOW_DATA_ATTR` and `ALLOW_ARIA_ATTR` are off.** Both default to true and are checked independently of `ALLOWED_ATTR`. `global.css` keys the dark palette on `[data-theme="dark"] *`, so a `data-` attribute would let content restyle its own subtree, and `aria-*` lets content lie to a screen reader about what it is.
- **`KEEP_CONTENT` stays at its default.** Setting it to `false` strips the text of every element, so every document renders as empty tags.
- **Links** are rendered but never trusted. Only `http`, `https` and `mailto` survive (`ALLOWED_URI_REGEXP`), so `javascript:` and `data:` links are removed. The hook sets `target="_blank"` and `rel="noreferrer noopener"` on every link, since the allowlist does not admit those attributes. They keep a link from navigating the session page away and from handing the destination this page's URL.
- **A task list keeps its state.** GFM's checkbox is an `<input>`, which the allowlist drops, leaving checked and unchecked items identical. The renderer emits `☑ ` and `☐ ` instead.
- **Tables, code and emphasis** render as marked produces them, inside the allowlist. Code is escaped, not interpreted.

### The sanitiser guard and the fallback

The guard is `typeof window !== 'undefined' && DOMPurify.isSupported === true`. It is not the presence of `sanitize`: DOMPurify's unsupported path returns its input unchanged, and the method exists either way, so the weaker check passes exactly where sanitising silently does nothing. Astro's build-time render has no DOM, so there `render` returns null.

`render` returns null for an empty source, an environment that cannot sanitise, a document `marked` throws on, and content that sanitises away entirely. It never returns the source as HTML. Callers fall back to the plain `whitespace-pre-wrap` text, so a failure degrades to plain text, never to an empty box.

### Deciding whether to render

`hasMarkup` decides whether a message needs the renderer at all, so plain prose skips it. It is deliberately over-eager: a false positive costs one render and a false negative shows literal backticks. It must stay linear. The obvious link pattern rescans to the end of the line from every `[`, and it runs on every message of every transcript, with a stored message bounded nowhere. `hasMarkup` tests for the literal `](` instead.

### Images

Without an image source, every image is its escaped alt text, written by a `renderer` override in `markdown.ts` as `(image: alt)`, or `(image)` with no alt. The override is used instead of rewriting the source. Source rewriting fired inside fenced blocks and inline code, so a report documenting Markdown had its examples changed, and it missed reference-style images and alts containing brackets. DOMPurify would otherwise drop the whole `<img>`, alt text included, so a report whose only content was a diagram would render as an empty box. The alt text is HTML-escaped, since the agent wrote it.

A report preview passes `render` an image source, `imageSource(jobID, origin)` in `deliverables.ts`. It is set only for the duration of one synchronous render, so no other render can see it.

- **What loads.** A link whose destination resolves inside the job's out directory becomes an absolute URL on that job's file endpoint, `/api/v1/jobs/<id>/file?path=…`, emitted as `<img>` with its alt and `loading="lazy"`. `outRelative` does the resolving. It unwraps an angle-bracketed destination, drops a query or fragment and decodes percent-escapes, and it refuses a URL or anything with a `:`, an absolute path, a leading `\` or `#`, a `\` or NUL after decoding, and anything that climbs out of the directory with `..`. It mirrors `jobs.OutRelative`, and the same table of cases tests both (`deliverables.test.ts`, `TestOutRelativeStaysInside`).
- **What the allowlist adds.** With an image source, DOMPurify's allowlist gains `img` with `src`, `alt` and `loading`. The hook removes any `img` whose `src` does not start with this job's file prefix, whatever produced it, including raw HTML. A remote, `data:` or escaping image is still alt text, and the render after a report render has no image allowed.
- **No request goes to a URL the agent chose.** The renderer does not know which images were collected and does not need to. An image that was not collected answers 404 from spov, and `missingImage`, a capture-phase `error` handler on the preview's container, replaces the broken picture with its alt text and a note, `[alt: an image that was not collected]`.
- **Defence in depth.** The web app's pages are served with `Content-Security-Policy: frame-ancestors 'none'; img-src 'self' data:` (`internal/webui/webui.go`), so even a bypass of the hook could not load an image from another origin. The app draws no other images.
- **Why it is acceptable.** Images are withheld in general for privacy, not because they run script. Serving collected images from spov's own origin removes the privacy reason: the browser asks spov, not a URL the agent chose, and nothing learns when the report was read. The extension is deliberate and narrow: only Markdown reports exist, and only collected rasters load.

The collection side is in DL-051: only a PNG, JPEG, GIF or WebP file under `out/` that a collected report links by a relative path is collected, typed by its first bytes. SVG is never collected, because served from spov's origin it could run script in the dashboard. The file endpoint serves the stored type with `nosniff` and `Content-Security-Policy: sandbox; default-src 'none'`. A report that links collected images downloads as a zip of the Markdown and images at their relative paths, and `spov jobs report --save <dir>` writes the same files.

## Rationale

- Sanitising rather than trusting is not a precaution about a hypothetical. An agent's output is the least trusted text in the system, and the transcript exists to read what an agent said while it may have been doing the wrong thing.
- A widened allowlist is a quiet change with no visible symptom until it is exploited. Any widening of the DOMPurify configuration is a security change and belongs under review, with `markdown.test.ts` as the guard. That file must prove that a remote image, a `data:` image and a path outside the file base still become alt text, that an `img` with any other `src` is removed even as raw HTML, and that the dangerous cases above stay out.
- The narrowing of `class` and the settings of `KEEP_CONTENT` and the data and aria options are traps because each looks safe in the wrong direction. `markdown.test.ts` catches each of them.

## Measurements

- **Class passthrough.** With no hook, `<p class="fixed inset-0 z-30 bg-paper p-4">` survives byte for byte and is a full-page opaque overlay carrying attacker text. Event-row classes are reachable the same way, which would let a sandbox draw text in spov's voice. Re-run: `cd web && bun run test -- markdown.test`.
- **`KEEP_CONTENT: false`.** It strips the text of every element, not only disallowed ones, so every document rendered as empty tags. Re-run: `cd web && bun run test -- markdown.test`.
- **The link pattern in `hasMarkup`.** On 200,000 open brackets the naive pattern took 14,054 ms, against 72 ms for the whole render. Re-run: `cd web && bun run test -- markdown.test` (the test requires under 1000 ms).
- **Bundle size.** `marked` 18.0.11 and `dompurify` 3.4.14 grew `dist/_astro` from 152 KB to 228 KB, about 76 KB. Re-run: `scripts/build-web.sh`.
- **Binary files through the sandbox.** `/api/fs/read` returns a binary file byte for byte (compared by sha256) and a file over 1 MiB whole. Re-run: `go test -tags integration ./internal/sandbox/ -run SD1 -v`.
- **Read shape.** `/api/fs/read` answers an error for a missing file and for an absolute path. Re-run: `go test -tags integration ./internal/sandbox/ -run S7FsReadShape`.

## Consequences

- The web build carries a Markdown library and a sanitiser, pinned exactly like `typescript` and `bun`. If either is swapped, the bundle sizes above are the figures to compare against.
- A rendered message is taller than its source, and its height changes as fonts load. The transcript tail's `atBottom` measurement is taken after layout settles, at the existing `requestAnimationFrame`, so a fresh render is not mistaken for a reader scrolling.
- A transcript message, rendered without an image source, always shows images as alt text. A report preview shows only images the job's file endpoint can serve.
- The list of tests in `markdown.test.ts` is the specification of the allowlist. A change there is a change to what an agent can put on the page.
