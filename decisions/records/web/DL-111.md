## Context

`buildTimeline` (DL-058) flattens every conversation's messages and every log event into one list, and `session` on a `LogEvent` is read nowhere in `web/src/lib/timeline.ts`. The speaker rules then run on the flat list:

- a message with role `user` is a right-aligned bubble, "your message". A subagent's task prompt is the first message of its own conversation, written by the parent agent, and is stored as `user`;
- a `session.inbox.enqueued` frame is promoted to a message by `spokenBy`, with the frame's own role, so the same prompt is drawn from the log as well;
- `messageStatuses` and the echo reconciliation (DL-059) key on `user` messages by id without asking whose conversation they are in;
- the child's assistant text is drawn unlabelled, as the main agent's, and its tool calls and thoughts are folded into the parent's runs, so a long review reads as the main agent doing 40 tool calls.

The result, seen on a hosted session whose agent ran a code-review subagent, is a transcript in which the reader appears to have said what the agent asked its subagent to do. DL-110 gives the page what it lacked: each conversation says whether it has a parent.

## Decision

`buildTimeline` takes the conversations with their `parent` and partitions its input by conversation before it applies any speaker rule:

- A **root** conversation (no `parent`) is drawn as today.
- A **child** conversation's messages and events never enter the main list. They go to a per-conversation timeline (`Map<conversation id, Entry[]>`) built by the same code, which the subagent card (DL-112) and the subagent view (DL-113) draw. Inside it, a message with role `user` is the task's prompt, a quiet "Prompt" row, never a bubble, and an inbox frame is never promoted to a person's message.
- Every rule that is about the reader is asked of roots only: promotion of `inbox.enqueued` to a bubble, the `ids` set that de-duplicates a person's message, `messageStatuses` (queued, processed, cancelled, not processed), and pending-echo reconciliation. A child's `session.inbox.*` frames never change the status of a message in the main list.
- The page's turn state is the root's: `turnInFlight` and `turnsEnded` take only the execution frames whose `session` is a root, which settles DL-059's known gap whichever way S-SA1 (DL-110) measures child execution frames. The signature gains the set of root session ids, and an unknown `session` counts as a root, so an older log with no parentage behaves as today.
- An event or message whose conversation is not yet listed (the log arrived before the conversation read) is held in the main list as today and moves out on the next read. The page already re-reads the conversation after a gap and when a turn ends, and DL-110 stores a child's parent before its first frame, so the window is the one the page already has for a new conversation.
- The window of 200 blocks (DL-070) and the fold counts (`runSummary`) are computed from the main list, so a subagent's activity cannot push the person's own messages out of the window.

Until DL-112 lands, a child's whole activity is drawn as one quiet folded row ("Subagent · N tool calls"), so splitting the timeline never makes work disappear. That row is the card's seed, not a separate design.

## Rationale

- The failure is one of attribution, and attribution is a property of the conversation, not of the message: a `user` item in a child's inbox is the parent agent speaking to a subagent. Fixing it per message (for example by guessing from the prompt text) would be a second heuristic beside the oldest-conversation one DL-109 already needed.
- Partitioning first and reusing one builder means a subagent's own view is drawn by the code that draws the main one, with no second set of speaker rules to drift.
- OpenCode does the same: the parent's transcript shows a task row, and the child's messages live in the child's own session view, never merged into the parent's.
- "An unknown session counts as a root" keeps the change fail-safe against a server that sends no parentage and against the one race above.

## Consequences

- `Conversation` in `timeline.ts` gains `parent?: string`, and `buildTimeline` returns the main list plus the children's, or takes a conversation to draw. `timeline.test.ts` gains the case that failed in production: a child with a `user` prompt and an `inbox.enqueued` frame, which must produce no bubble and no status change.
- `steer.ts` functions that read the log (`turnInFlight`, `turnsEnded`) change signature, and `sessiondetail.svelte.test.ts` pins that Interrupt stays drawn while a child's turn ends mid-turn.
- AGENTS.md's "transcript draws work, not plumbing" paragraph gains a sentence naming the partition when this is implemented.
