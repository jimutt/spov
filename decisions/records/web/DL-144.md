## Context

DL-112 reads a subagent card's state from the child's own frames, and falls back to the call that started it when the child has none: a finished call that was not a background call means the child is done. From OpenCode 2.3.0 every `subagent` call returns at once and its input carries no `background` flag, so that fallback calls a child done before its first frame is read.

The page also draws the agent as working only while the main conversation's turn is in flight (DL-111, DL-059). With background subagents the main turn ends while children work, so the page looks idle during the longest part of a delegated task.

## Decision

- A finished `subagent` call says nothing of its child, whatever its input. With no frame of the child's read yet the card is starting, and running once the child has frames with no execution ending. `DelegatedCall.background` and the reading of the `background` input are removed. A call that failed started no child, and its card stays failed. A finished call with no conversation behind it that names no child (a log recorded before parentage, DL-110) has nothing to wait for and stays done.
- A child a call names that no conversation lists as one (a log from before parentage, or a subagent started after the page read the conversations) is judged from its own frames in the log all the same. A frame of a session the page holds no conversation for, once the conversations have been read, makes the page read them again, once per such session (`unlistedSessions`), so a subagent started while the page is open becomes a child; DL-111 assumed a re-read the page did not make.
- `subagentsWorking` (a plain function beside `subagentState`) counts the children, at any depth, whose state is running or starting, from the cards the timelines drew. While the main turn is not in flight and the count is above zero, the composer's status line reads "1 subagent working" or "N subagents working", and a job's sidebar state line adds the same words. A session that has ended counts none.
- Interrupt stays tied to the main conversation's turn (`canStop` is unchanged): it is not drawn while only subagents work, and the page offers no way to stop a subagent. The status line's explanation (`controlsNote`) says a message sent now is read when the agent's next turn starts.
- Sending is unchanged: `sendability` does not read the count.

## Rationale

The child's own frames are the only source that says how a child is going, so the fallback should claim nothing. The count is derived from what the page already holds, so it asks the server for nothing. Interrupt is left alone because `POST /sessions/{ref}/interrupt` addresses the main conversation, and what it does to a running child is not measured; offering a control whose effect is unknown would be worse than offering none.

## Measurements

- S-SA3 (local, at 2.3.0): an interrupt of the parent does not stop a running child, whether the parent is idle or its own turn is in flight; the parent's tool is aborted and the child's is not. Interrupting the child's own session stops it (`session.execution.interrupted`, reason `user`), and its report reaches the parent with `state="cancelled"` and starts a parent turn. So Interrupt on the page, which addresses the main conversation, never stops a subagent.
- The fixture the page's tests read (`subagent.fixture.ts`) is S-SA1's 2.3.0 capture passed through the real recorder (`TestWriteTheSubagentFixture`), beside the 2.2.5 foreground and background pairs.

## Consequences

- A session recorded before the pin moved still draws correctly: its foreground children have their own frames, which decide first.
- Stopping a running subagent from the page stays unavailable. S-SA3 has since measured that only an interrupt of the child's own session stops it; offering that is a decision of its own.
- At 2.3.0 a child's report reaches the parent as a `synthetic` inbox item, which the page draws as a spov-tagged message carrying the report's `<subagent>` markup, beside the card that already shows the child's conclusion. How to draw it is not decided here.
