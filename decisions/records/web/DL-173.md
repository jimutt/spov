## Context

The transcript tagged every synthetic message "spov" (DL-058): spov's job supervisor and job plugin send synthetics, and so did nothing else spov ran. Plugins do too. `opencode-rules` delivers its rules as a synthetic message ("The following rules were injected by a plugin…"), so a plugin's words were drawn as spov's, and long injected context sat in the conversation at full length.

spov sends synthetic messages only into a job's session: the opening goal (`openJob`) and the job plugin's continuations, replies and stop marker. An interactive session receives none from spov.

## Decision

- In a session with no job, a synthetic message is drawn as added by OpenCode or a plugin: a folded line that says so, opened by a press to the message's text, never tagged "spov".
- In a job's session a synthetic message keeps DL-058's drawing, the "spov" tag and the stop marker's sentence.
- A subagent's report stays hidden (DL-144).

## Rationale

Who sent a message is part of what it means. The page cannot tell a plugin's synthetic from OpenCode's own, so it names both, and folding keeps injected instructions from crowding the conversation.

## Consequences

- A plugin's synthetic in a job's session is still drawn as spov's; jobs do not take plugins (DL-171), so only a repository's own `opencode.json` loaded by a sync job could cause it.
- "a synthetic message in a session without a job" in `sessiondetail.svelte.test.ts` guards it.
