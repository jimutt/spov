## Context

DL-119 and DL-120 give the server sandbox templates. The browser is where they are made and the main place they are picked.

## Decision

### Settings

`/settings` gains a **Sandbox templates** section (`Templates.svelte`, logic in `web/src/lib/templates.ts`), below the routed credentials.

- The list shows each template's name, description and a one-line summary of what it sets (`templateSummary`: "egress install, 2 credentials, 3 variables, rust and postgres@16", and nothing for a setting it leaves out). A template that lists a credential the user does not hold says which.
- **Add template** and each row's **Edit** open one form; **Delete** is behind `ConfirmAct.svelte`'s second press. A rename is not offered: the name is the key.
- The form's controls, each with a "not set" state that leaves the setting out of the template:
  - egress: not set, `open`, `install` or `agent`, and extra domains when the preset is not `open`;
  - routed credentials: **Default** (not set), **None**, or **Only these**, a checklist with one row per credential name (the user's own where both they and the organisation hold the name, since that is the one a launch attaches), each with its hosts and attach mode. **Only these** with nothing ticked cannot be saved; **None** is how a template attaches nothing;
  - variables: rows of name and value;
  - add-ons and apt packages: one per line, as `name` or `name@version`;
  - git access: not set, `repos` or `all`, with DL-043's warning beside `all`.
- A save is a `PUT` of the whole template. The server's 422 text is shown as it is. Enter never submits, and one pending flag disables Save while a write is out.
- Where the endpoints answer 501 the section is not drawn.

### The launch forms

`/sessions/new` and `/jobs/new` gain a **Template** control (`TemplatePicker.svelte`) under the repository picker.

- Its first option is **None**, which is selected on every load and sends no `template`. The last choice is not remembered, and no template can be marked as a default.
- A chosen template is sent as `template`, and its summary line is shown under the control.
- With no templates the control is one quiet line linking to Settings, not an empty select.
- `/sessions/new` therefore sends what it sends today (`repos`, and a model when one is chosen) and, when a template is chosen, `template`. On `/jobs/new` a control the form already has (git access, the model) is sent only when the person set it, as today, so it wins over the template (DL-120). The job form's git access control names where its unset value comes from; with a template that sets git access chosen, it names the template, not the profile.
- A refusal that names the template is shown as the form's error, with the form left as it was.

### The session page

The collapsed Sandbox `details` in the sidebar gains a **Template** row with the name, when the session was launched from one. The settings themselves are already drawn there (credentials, variables, egress).

## Rationale

None-by-default is the user's decision: a launch that picks nothing must behave as it does today, and a choice the browser remembered by itself would attach credentials to a launch the person did not think about. The CLI's `sandbox.template` (DL-122) is different in kind: the person wrote it into their own file. Showing the summary under the picker lets them see what a template will attach before spending money.

"Not set" on every control mirrors DL-119's rule that a template says only what it is for.

## Consequences

- DL-061's rule that `/sessions/new` sends `{repos}` alone becomes "`{repos}` and an optional `template`".
- The Settings page gains a third kind of form. Its seeding must follow `seedField`'s rule (return the argument unchanged when nothing changed) or it loops (DL-062).

## Implementation notes

- vitest in `templates.ts` for the summary, the request built from a draft (a "not set" control is absent from the body, **None** sends `no_credentials`, **Only these** with nothing ticked is a problem and not a request), and the checklist's three states.
- Mounted tests only for wiring: None sends no `template`; a chosen one is sent; the picker is a link when there are none.
- Look at the form and both launch pages at 390 px, 768 px and 1280 px (DL-106). The picker goes in the one options wrapper, never a second copy.
