## Context

An unattended job's conversation gets no title from OpenCode, because nobody writes in it (DL-149). The prep pass (DL-047) is already one model call that reads the goal before the job is provisioned.

## Decision

- The pass's answer gains `title`: a name for the task in at most eight words, asked for in the same call and the same JSON object as the summary and the proposed check. No second call is made for it. The parser flattens it to one line and bounds it (`MaxTitleBytes`), as it does the summary.
- The title is kept on the job row (`store.Job.Title`, a new nullable column, migration 00042), written with the assessment in the same write and cleaned and bounded as DL-149 says. `UpdateJob` sets it only while the row has none, so no later write changes or clears it.
- A pass that gave only a title is a pass that ran: it is recorded, and a redelivered attempt pays for no second call.
- It is used only as DL-149 says: as the session's title while the main conversation has none. It never reaches the agent: the opening text (`openingText`) is unchanged.
- A job created with `skip_prep`, a pass that fails or cannot be recorded, and an answer with no usable title leave the job without one. That is not an error and is not retried.
- The goal is untrusted and so is the title: the system prompt's rules for the goal apply, and a title is never read as an instruction or a check.

## Rationale

The call is already paid for and already reads exactly the text a title should summarise. Keeping the title out of the opening text keeps the agent's input what DL-047 decided.

## Consequences

- A job run without the pass shows its repository as its headline, as before.
- The pass's fake completer and its contract with each provider's structured output gain one field.
