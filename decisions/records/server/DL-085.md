## Context

A resumed session keeps its row and gets a new sandbox (DL-087), so a session has several sandboxes over its life. Today `store.Session` holds one `SandboxID`, and usage bills a session from `CreatedAt` to `StoppedAt` (`billableWithin`, DL-009). A session resumed a day later would be billed for the day it was stopped.

The exit snapshot of each sandbox (DL-084) is ready seconds after the sandbox ends. It can be fetched later from the sandbox ID alone, so a server that restarted can still collect it.

## Decision

A new table, `session_runs`, has one row per sandbox a session had, numbered from 1. The memory store and `statefile` carry the same records. Each row holds:

- `sandbox_id`, `started_at` and `ended_at`;
- `origin`: `launch`, `snapshot` or `transcript`;
- `snapshot`: the exit snapshot's image ID once it is kept, empty otherwise;
- `snapshot_state`: `none` (created without one), `pending`, `kept`, `failed` or `deleted`;
- `snapshot_at`: when the snapshot was kept;
- `opencode`: the OpenCode version the run's sandbox ran (DL-088).

`store.Session.SandboxID` stays the current run's sandbox, for the code that reads it today. The session's `Booted` image stays the launch's image.

A launch writes run 1 in the transaction that records the sandbox, and each resume writes the next run. A run ends when its session is marked `stopped` or `failed`, or when the reconciler reaps its sandbox (DL-004); `ended_at` is set in the same write as the state change.

**Collection.** `Service.CollectSnapshots` runs once a minute where the reconciler runs. It calls `Provider.ExitSnapshot` for every `pending` run whose sandbox has ended, waiting at most 30 s per call. A kept snapshot is written to the run. A run still pending 30 minutes after it ended, or one whose snapshot Modal reports failed, is marked `failed`, and the session is left resumable from the transcript (DL-089). Nothing on a read path calls Modal for this (DL-018).

**Usage.** `billableWithin` sums each run's stretch between `started_at` and `ended_at` (now for the live run) inside the window, instead of the session's `CreatedAt` to `StoppedAt`. A session from before this change has no runs and is billed as before, from its own times. This amends DL-009.

## Rationale

A run per sandbox is what "reopen the same session" needs underneath. The reconciler, the recorder and the cost each ask about one sandbox at a time, and the row answers for the current one while the runs keep the history.

Snapshots live on the run rather than in DL-016's image registry: registry entries are keyed by an image name, and an exit snapshot has only an ID. The registry's rule is kept, though. The store says whether a snapshot exists, not Modal, and a run marked `deleted` is never booted.

Collecting after the end, by sandbox ID, from where the reconciler runs means a restart or a replica change loses nothing. The 30-minute limit covers a snapshot Modal never finishes without leaving it pending forever.

## Consequences

- A migration adds `session_runs`, and backfills run 1 for live sessions only.
- `Fake` gains exit snapshots, so the collection and the resume paths are tested without Modal.
- Usage for a resumed session counts only the time a sandbox ran.
