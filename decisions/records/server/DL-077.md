## Context

A server built without the proxy (a plain `go build`) puts forge tokens and provider keys in the main container, and a hosted one runs that way only with `SPOV_TOKENS_IN_SANDBOX=1` (DL-034). A routed credential has no such fallback worth having: its whole point is a secret the agent does not hold. Because every session gets routed credentials by default (DL-075), the user also needs to see which ones a session holds.

## Decision

### No proxy, no routed credential

A launch whose attached set (DL-075) is not empty is refused when the server has no proxy image (`Deps.ProxyImage`, which is the launcher's, unset), locally and hosted, `SPOV_TOKENS_IN_SANDBOX=1` included. The refusal is a 422 at create, before any row or anything billable (`refuseRoutesWithoutProxy`), naming the credentials and saying how to go on: launch with `--no-credentials`, or rebuild with `scripts/build-proxy.sh`. The launcher refuses `Options.Routes` again without a proxy image, before it mints anything (`session.ErrRoutesNeedTheProxy`), so no other caller can put a secret in the main container. A launch with nothing attached is unaffected.

Every published binary embeds the proxy. Distribution's release check (plan part 3, not built yet) asserts that the built binary holds a real `internal/proxybin` image, so a release cannot ship the placeholder.

### Named on the page

- `SessionView.routed_credentials` lists each attached credential: name, tier (`user` or `org`), hosts, paths, scheme, user, header and preset, never the secret. The session page draws them under the forge credentials, a tag (`routedCredentialTag`) and a line with the hosts written out (`routedCredentialLine` in `web/src/lib/format.ts`).
- A credential the launch left out is named in the launch's progress and the session log with the reason: the organisation's credential on a host a personal one took (DL-075), a project file's narrowing, a missing secret (DL-073).
- The launch log names the routed credentials the proxy holds (names and hosts only), as it does for provider keys.
- `spov ls --json` and the session API carry the same list.
- Settings lists the user's routed credentials (`RoutedCredentials.svelte`: name, route, attach mode, and a missing secret) and offers remove, through DL-073's endpoints; a server that can hold none answers 501, which the section says. Adding one from the browser is a later change, and the section names the command.

## Rationale

Falling back to the main container would turn a misbuilt server into a credential leak that looks like a working launch. Refusing only when something would be attached keeps a placeholder build usable for development without routed credentials.

Naming every credential with its hosts is the check that makes a default-everything rule safe: the user can see at a glance what a session can reach, as they can for forge credentials (DL-043).

## Consequences

- A developer on a placeholder build with any routed credential must pass `--no-credentials` or build the proxy.
- Tests: `TestALaunchWithoutTheProxyRefusesRoutedCredentialsAtCreate` (which also launches with none), `TestALaunchWithoutTheProxyRefusesRoutedCredentials` (the launcher's guard), `TestTheSessionViewNamesItsRoutedCredentials`, and `format.test.ts` for the line.
