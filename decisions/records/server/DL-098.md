## Context

A synced session (DL-027, the default inside a checkout since DL-095) records the branch and the base commit it started from. The launch's bundle of unpushed commits is passed to the sandbox in memory and never stored. A transcript resume (DL-087, DL-088), used when no exit snapshot exists, clones the repositories fresh and seeds the clone again from the stored branch and base. When the base was never pushed, the fresh clone cannot reach it, and the seed's `checkout -B` fails, so the resume fails. A synced session whose repository has no remote at all cannot even be cloned.

## Decision

This amends DL-027's rule that the bundle travels only with the launch, and DL-087's transcript resume of a synced session.

### The CLI sends the base again

`spov resume`, and `spov attach` when it resumes a stopped session, send a bundle of the session's base commit with the resume (`sync_bundle` on `POST /api/v1/sessions/{ref}/resume`, base64, the same 16 MiB bound as a launch's). They do so only when all of these hold:

- the session has a sync seed;
- the server says the resume is from the transcript;
- the working directory is a checkout of the session's repository (`verifySyncCheckout`);
- that checkout holds the base commit.

The bundle holds the commits from the newest remote-tracking ancestor of the base up to the base, as a launch's does, or the base's whole history when there is no such ancestor. A session with no platform always gets the whole history, even when the checkout has a remote, since its sandbox has no clone to build on. When the base is already a remote branch's tip, nothing is sent: the clone fetches it. Otherwise, when the CLI cannot send it, it says why in one line. The bundle is used for that resume only and, as at launch, never stored. Its tip is named by a temporary ref of its own (`refs/spov/resume-seed-<pid>-<time>`), deleted once the bundle is made.

The resume route's body limit is the launch's (`MaxSessionBodyBytes`), set on the huma operation itself. huma caps any operation that names none at 1 MiB, which until now also held a launch's bundle to about 768 KiB, whatever DL-027 said. A bundle on a snapshot resume, or on a session that is not synced, is ignored without being checked.

### Without one, the default branch

A transcript resume with no bundle, whose base the fresh clone cannot reach, does not fail. The seed stops before `checkout -B`. The workspace stays on the clone's default branch. The launch's progress notes that the launch's unpushed commits are not in it, and that stopping the session and running `spov resume` inside the checkout brings them. The note is in the launch's progress only, not the session's log. If the bundle fails to unbundle in the sandbox, the seed's fallback fetches every ref the bundle names, not `HEAD`, which a resume bundle lacks. A first launch whose base cannot be reached still fails, as DL-027 has it.

A synced session with no platform (DL-027's local-bundle mode) has nothing to clone. Its transcript resume without a bundle is refused at the API with a 422 that names `spov resume` inside the checkout, before a sandbox is created.

The session's sync seed is unchanged either way. A later `spov stop --sync` exports against the recorded base. When the sandbox does not hold it, the export bundles from the remote's default branch, which the local checkout has too, rather than the whole history.

`git.ApplySync` now lands in place only when the sandbox's head descends from the local head. DL-027 also allowed a local head at the base when the sandbox's head does not descend from it. After a fallback resume, or a rewritten history, that reset dropped the local branch's commits, so such an export lands on the `spov/<session>` branch instead.

## Rationale

- The checkout the session came from almost always still holds its base, so the CLI can supply what the server deliberately does not keep.
- Falling back keeps the conversation resumable from the browser and from another directory. A transcript resume already says uncommitted work is gone; it now also says which commits are missing, rather than failing outright.
- Storing the bundle would make every synced session's row up to 16 MiB larger to serve the rarer path.

## Consequences

- A resume from the browser, or from another directory, of a session with unpushed commits comes back without them, and says so.
- A local-only synced session can be resumed from its transcript only from its checkout.
