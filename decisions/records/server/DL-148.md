## Context

The session list shows each session's last message (`LastMessages`, DL-115: the newest message of a root conversation). OpenCode stores more than speech as messages: a turn's end is a message of type `idle`, a model switch is one of type `model-switched`, and an assistant message that only called tools has no text. Each has no text, so a finished session's row read "idle: …" and said nothing about the session. Others carry text but are not anyone's words to the reader: spov's synthetic items (a job's goal, the loop's continuations, its `SPOV_LOOP_STOPPED` stop marker) and types such as `shell`, `system` or `skill`, so a job's row could preview as `spov: SPOV_LOOP_STOPPED {"reason":…}`.

## Decision

`LastMessages` answers each session's newest root-conversation message whose role is `user` (a person's) or `assistant` (the agent's) and whose text is not empty or only whitespace (`store.PreviewRole`). The role is OpenCode's message type, which the recorder stores as the message's role. spov's synthetic items and every other type are never a preview. A session with no such message is absent from the answer, as one with no message is, and its row says nothing is recorded yet.

Postgres filters in the query (`role in ('user', 'assistant')`, and `btrim` over space, tab, newline and carriage return) and the memory store with `PreviewRole` and `strings.TrimSpace` in its scan.

## Rationale

A preview exists to say what a session is about. A marker with no words cannot, and neither can spov's own plumbing; the newest thing the person or the agent said is the most recent thing the reader would recognise as the conversation.

## Consequences

- The preview of a finished session is the agent's or the person's last words, not the turn's end marker or spov's stop marker.
- An unattended job's row has no preview until the agent first answers, since its goal is a synthetic item.
- A type OpenCode adds later is never a preview until this list names it.
