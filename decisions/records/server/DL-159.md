## Context

A reader should be able to choose a model's reasoning mode in a running session, and the choices must be exactly what that model accepts, never generic levels. OpenCode calls these a model's variants. The pinned build lists them per model at `GET /api/model` (`Model.variants[].id`, in its own order), and they vary per model and provider: `none, thinking` on some OpenRouter models, `low` to `max` on Claude, `minimal` to `high` on gpt-5-nano. models.dev's `reasoning_options` explain most of them, but OpenCode applies its own exceptions (49 of 594 models measured at 2.3.0), so re-deriving them in spov would drift. Only a sandbox's own OpenCode knows for certain what it accepts, and it lists only the providers that sandbox holds a key for.

## Decision

- When the recorder attaches to a sandbox it reads `GET /api/model` once, before catching the store up, and keeps for each model that has variants its `providerID/id` and its variant ids in OpenCode's order. Models without variants are not kept.
- The result is written with the sandbox it was read from, through a setter of its own (`SessionStore.SetModelVariants(org, id, sandbox, variants)`; `Update` keeps the stored values, as with `SetGitToken`). An attach to a sandbox whose list is already stored does not read again, so a redial or a restart of the server reads nothing; a resumed session's new run reads its own. Postgres keeps it in columns of `sessions` (migration 43), the memory store on the session row, journaled like every write.
- The read is bounded: its body at `MaxModelListBytes` (4 MiB) and what is kept at `MaxModelVariantsBytes` (256 KiB); a read that fails, times out, is over a bound or does not parse writes nothing and is logged once, and the recording goes on, so the reasoning choice is simply absent for that run. The read is added to `contract.Used` and the recorder's fake serves it through `contract.Checked`.

## Rationale

Reading the sandbox gives exactly what that build and that sandbox's providers accept, with nothing to regenerate on a pin bump or a release. DL-018 makes the recorder the only reader of a sandbox and forbids reads on a timer; this is one read per run at attach, which is where the recorder already reads the message store, so it adds no idle-clock cost worth measuring and no read path a browser can reach.

## Consequences

- Until the recorder has attached to a run, no reasoning choice is known for it.
- About 560 KB is read per run (2.3.0, ten providers' keys), and some tens of KB stored per session.
- A model OpenCode lists without variants offers only its default.
