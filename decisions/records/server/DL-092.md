## Context

DL-091 keeps a local server's sessions on disk. A session's row and runs change in place, a few times in its life. Its transcript grows to thousands of events and is appended to, a frame at a time, while it runs.

## Decision

Each session is a directory, `sessions/<session-id>/`, mode 0700, holding two files, mode 0600:

- **`session.json`**: `{"format": 1, "session": {...}, "runs": [...]}`, the session's row and its runs. It is rewritten whole on every change, through a temporary file renamed over it, so a crash leaves the old one or the new one.
- **`transcript.jsonl`**: one JSON record per line, appended and never edited. The first line is `{"type":"header","format":1,"session":"<id>","created":"<RFC 3339>"}`, and each line after it is one of:
  - `{"type":"conversation","conversation":{...}}`
  - `{"type":"message","message":{...}}`
  - `{"type":"event","event":{...}}`

  Each carries the stored row whole: the last record for a conversation's ID or a message's ID wins, and events are kept in position order. A batch of rows from one write is one `write` call.

**The record types are the journal's own,** with explicit JSON names in `internal/store/journal.go`, not the store's Go types. A rename in the store cannot then change what is read. A change to a record's meaning bumps `format`, and the reader refuses a format it does not know rather than guessing. Byte fields (an event's or a message's raw frame, a conversation's info) are written as JSON values when they hold valid JSON, so `jq` reads them. Anything else is written as base64, flagged on the record.

**Reading back:**

- A last line that does not parse is a write the process died in. It is dropped, and the file is cut back to the last good line before anything is appended.
- A bad line elsewhere is skipped with a warning naming the file and line.
- A transcript whose superseded records outnumber its live ones is compacted at start: rewritten through a temporary file with only the live rows, conversations first, then messages, then events by position.
- A session directory with no readable `session.json` is skipped with a warning and left on disk.

## Rationale

Splitting the two files by how they change keeps each write cheap and safe. The row is small and wants to be read whole, so rewriting and renaming it is atomic. The transcript is large and only grows, so appending is O(1) and a crash costs at most its last line.

Typed records with the whole row are Claude Code's convention, and they make a transcript readable on its own. Last-wins replay makes an upsert (a message re-read at a turn's end) an append rather than an edit.

## Consequences

- `jq -c 'select(.type=="message") | .message.text' transcript.jsonl` reads a session's conversation. The format is documented in `docs/local-history.md`.
- A message upserted repeatedly costs a line each time until compaction.
- A format bump needs a reader for the old one, or the old sessions are skipped and say so.
