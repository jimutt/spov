## Context

`Recorder.readMessages` (`internal/server/recorder.go`) reads `/api/session/{id}/message` with no `limit`, `order` or `cursor`, although the pinned OpenCode document's operation takes all three (DL-017, DL-035). If OpenCode applies a page size, a conversation longer than one page never has its older messages stored, and the transcript's recovery from `messages` misses them.

## Decision

Proposed: measure the page size the pinned build applies, then read with `cursor` until the end when a page is full, and add the call's parameters to `contract.Used`.

## Consequences

A long conversation is stored whole, and an OpenCode bump that changes the paging is caught by the contract check.
