## Context

The modes offered before a launch (DL-187) are the build's and the organisation's, not the sandbox's own: a sandbox lists only the providers it holds keys for, a seen list can be wrong (DL-186), and a stored default is not checked at create. S-MV1 shows that a mode the sandbox does not offer, set through the model endpoint, fails every turn, which on a job ends the run as `turn-failed` after its retries (DL-048).

## Decision

- Where spov sets a new conversation's model (`jobConversation`, `firstConversation`, and a resume's), a model with a mode is first checked against the sandbox's own list: the one the store holds for the session's current sandbox (DL-159), else one read now from `GET /api/model` with DL-183's waits and bounds, kept as the recorder would keep it. The read is part of the opening, an act like the model write that follows it, never on a timer.
- When the list names the mode for the model, the model is set with it. Otherwise, or when no list could be read, the model is set without the mode, and the session's log gets `spov.session.model.mode.dropped` with the model, the mode and what the sandbox offers (or that it could not be read). The page draws it as a quiet note (`NoteMarkers`): "<mode> is not a reasoning mode <model> offers in this sandbox; it runs on the model's default."
- The model switch keeps DL-160's refusal: a person choosing a mode in a running session is told, never silently given the default.

## Rationale

An unattended job, and every run of a schedule, should not fail because a mode it was given months ago is gone. Running on the default with a note is what a person would choose, and the note says so where they read the run. The sandbox's own list is the only one that is certain; reading it at the opening is one bounded read per conversation spov opens.

## Consequences

- A conversation a person opens from their own client (the TUI) takes the config's model, which carries no mode (DL-187), and runs on the default.
- A job's verdict does not mention the dropped mode; the transcript does.
