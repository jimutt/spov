## Context

The sessions list and the session stream decorate each row with `last_message`, read by `ConversationStore.LastMessages` as each session's newest message across every conversation (`viewsOf`, `StreamList`). While a subagent runs, its messages are the newest ones, so the row in the list shows the subagent's task prompt, a `user` message, as what "you" last said, or its replies as the agent's. The list is the first thing a reader sees, and it is the same misattribution as in the transcript (DL-111) one screen earlier.

The browser's `speaker()` (DL-058) draws the preview with the role the server sent, so it cannot correct this itself.

## Decision

`LastMessages` answers from conversations with no parent (DL-110) only. In Postgres the query joins `conversations` and filters `parent_opencode_id IS NULL`. The memory store answers `LastMessages` with a scan of its messages, not from an index, so it skips a message whose conversation has a parent, read at query time; a conversation that gains a parent later (a catch-up filling in a failed first read) leaves the preview at once with nothing to undo. A session whose only messages are a child's has no preview, as one with no messages has none.

Nothing else on a list row changes: the job badge, state, cost and run facts are the session's, not a conversation's. `SessionView` gains no field, so the generated client does not change.

## Rationale

- The preview exists to say what the conversation is about and who spoke last. That is the person's conversation by definition, and a subagent's activity is shown on the session's page.
- Filtering in the store query keeps the list's cost at one query (DL-012, DL-018); filtering after the read would make a session whose newest message is a child's show nothing, or force a second read.
- The memory-index rule is AGENTS.md's and DL-071's: a new write must update the index and journal its undo, or a long session turns the read back into a scan.

## Consequences

- `storetest` gains the case for both stores: a root message, then a newer child message; the preview is the root's, and a session whose only messages are a child's has none.
- The gap between a child's first frame and its parent being stored is closed by DL-110's read-before-upsert; if that read failed, the preview can show the child's message until the next catch-up, the same bounded window the page has.
- Verdict, import and recorder reads (`ListMessages`) are untouched: they want every conversation.
