## Context

DL-159 has the recorder read a run's `GET /api/model` once, beside its first attach, and keep what it says, never on a timer. At 2.3.0 the list was there the moment OpenCode answered, filled from the models.dev snapshot built into the binary.

OpenCode 2.4 builds the list a few seconds after the server starts. Measured on 2.4.2 with only provider keys in the environment, online and with the network blocked: the list names no model right after the server is healthy, and about a hundred three seconds later. A recorder that attaches in those seconds would keep an empty list as the run's, and the session page would offer no reasoning mode until the sandbox changed.

## Decision

A model list that names no model at all is a list not built yet, never an empty answer: `parseModelVariants` returns `errNoModelsListed` for it, and nothing is kept. The same read then asks again up to `ModelListWaits` (10) more times, `ModelListPause` (1 s) apart, through the recorder's `sleep` seam and inside the read's `SandboxReadTimeout`. A list that names models none of which has variants is still kept, as an empty set. A sandbox that never lists a model is one failed read, counted against `MaxModelListReads` and said once, as before.

## Rationale

The pauses are bounded and happen only in the seconds after an attach, so they amend DL-159's "never on a timer" without reopening what it guards against: they cannot keep a sandbox billing, which DL-018 is about. Treating only a list with no model at all as not built keeps a real answer, even one with no reasoning modes, from being asked for again.

## Consequences

A run whose sandbox never lists a model costs at most eleven reads over ten seconds instead of one. A new build that answers with no model for longer than that fails the read, and the next attach tries again, as for any failed read.
