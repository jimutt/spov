## Context

The local journal (DL-091) grows by every session's transcript. Claude Code cleans its transcripts up after 30 days by default; OpenCode keeps everything. Exit snapshots, which a local server now takes too (DL-091, DL-084), are kept 7 days by default (DL-086), and a session whose history is gone cannot be resumed.

## Decision

`history.retention` (`SPOV_HISTORY_RETENTION`, default `720h`) is how long after a session stopped its journal is kept. `0` keeps it forever. Like the other server-only keys it is read from the user file and the environment, never a project file (DL-026), and it means nothing to a hosted server.

`store.OpenJournal` prunes at start, before the server serves. A session that is not live and stopped longer ago than the retention has its directory deleted and is removed from memory. A session one of whose runs still has a kept snapshot is left until pruning has deleted that snapshot (DL-086), so a history is never pruned from under a snapshot that would still resume it. A local server restarts often (it exits after a minute idle), so pruning at start is enough.

A local server takes exit snapshots on the same terms as a hosted one when its build embeds the proxy. `snapshots.*` apply to it; that amends DL-086, which named hosted servers only.

## Rationale

Thirty days follows the convention Claude Code's users already know, and it bounds both the disk and the start-up read. Keeping a history while its snapshot is kept means the two retentions never disagree about whether a session can be resumed.

## Consequences

- `docs/configuration.md` gains `history.retention`, and the configuration sample test covers it.
- Setting `snapshots.retention` above `history.retention` keeps those histories as long as their snapshots.
