## Context

Modal keeps an exit snapshot for 30 days and publishes no storage price for it (DL-084). Every interactive session under the proxy leaves one behind. Kept until Modal's own expiry, a busy deployment would hold a month of images nobody will resume.

## Decision

Three server settings, read only from the server's config and its environment (`Env.ServerConfig`; a project file or user file cannot set them, DL-026):

| key | env | default | meaning |
|---|---|---|---|
| `snapshots.enabled` | `SPOV_SNAPSHOTS_ENABLED` | `true` | off means no sandbox gets an exit snapshot (DL-084) |
| `snapshots.retention` | `SPOV_SNAPSHOTS_RETENTION` | `168h` | how long after its run ended a snapshot is kept |
| `snapshots.max_per_user` | `SPOV_SNAPSHOTS_MAX_PER_USER` | `20` | how many kept snapshots one user may have; `0` means no cap |

The same keys apply to local and hosted servers. A retention over 720h (Modal's 30 days) or under 1h is refused at startup, as is a negative cap.

`Service.PruneSnapshots` runs daily where the reconciler runs, beside `RunImagePrune` (DL-016), and when a run's snapshot is kept. It marks `deleted` on every kept snapshot whose run ended longer than the retention ago, and on each user's oldest kept snapshots beyond the cap. Then it deletes each marked image from Modal. A delete that fails is retried on the next pass; the run stays `deleted` in the store either way, so it is never booted.

A run whose snapshot was superseded is marked `deleted` too: once a later run of the same session has its own kept snapshot, the earlier one is pruned. S-SR1 showed a later generation boots after the earlier one is deleted.

Turning snapshots off stops new ones. It does not delete those already kept, which age out under the retention.

## Rationale

Deployment config only, as agreed: an operator pays Modal's bill, and a per-user setting would add a layer with no one asking for it.

Marking before deleting follows DL-016, so a crash between the two never leaves a run pointing at a deleted image. Pruning a superseded snapshot keeps the count to one per session in the common case, so the cap mostly counts sessions.

## Consequences

- `docs/configuration.md` documents the three keys, and the configuration sample test covers them.
- Prune is one more daily pass with a Modal call per image. Its counts go in the metrics document (DL-011).
