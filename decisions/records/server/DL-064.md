## Context

`spov serve --local` defaults to `127.0.0.1:0` (DL-002), but `runServe` in `internal/cli/serve.go` binds whatever `--listen` names, and the flag's help says only what the default is. The CLI refuses a state file whose URL is not on loopback, so a local server on another address is no use to the CLI. It would still listen on the network, guarded only by its generated token.

## Decision

With `--local`, `spov serve` refuses a `--listen` address that is not on loopback, with an error that names the hosted mode as the way to serve a network, before it migrates or opens anything. An address with an empty host (`:8080`) binds every interface and is refused too; `localhost`, `127.0.0.1` and `::1` are accepted, and an address with a zone is refused. The rule is `loopbackHost`, the one the CLI also applies to the URL in the state file. The flag's help says so, and `TestALocalServerRefusesANetworkAddress` covers both sides.

## Consequences

A local server can never be reached from another machine by mistake. Anyone who wants a networked server runs it hosted, with its own token and configuration (DL-010).
