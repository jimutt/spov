## Context

Some stopped sessions have no usable snapshot:

- it was pruned or expired (DL-086), or Modal failed to take it (DL-085);
- snapshots are off, or the session ran without the proxy (DL-084);
- the deployment's OpenCode pin has moved since (DL-088).

The store still holds every conversation: each message whole in `store.Message.Raw` (DL-069), each conversation's ID and title, and its events keyed by conversation and durable seq (DL-017).

Spike S-TR1 (`internal/server/transcriptimport_integration_test.go`, 2026-11-05 and 2026-11-06, local, pinned 2.0.22) used `POST /api/experimental/session/import`, which takes `{info, messages}`. Here `messages` is the list `GET /message` returns, which is what `Raw` holds, and `info` is a `Session.Info`. It found:

- a conversation rebuilt from the stored messages in a fresh OpenCode kept its ID and every message;
- on the next turn the model was sent the old history;
- the imported conversation's durable log starts again. The first server's turn ran seq 2..13, and the imported conversation's next turn ran 5..14. Frames stored by conversation and seq would collide with the old ones, and DL-017's gap rule, which compares against the last stored seq, would see nothing new.

S-TR1 used the real `Session.Info`, which the store does not keep today.

## Decision

**The sandbox.** A transcript resume boots a fresh sandbox:

- its image is the variant for the recorded add-ons at the deployment's current pin, picked and built as at launch (`pickVariant`, DL-016). A session launched on a custom `sandbox.image` boots that image again if the registry still has it; otherwise the resume is refused, naming the image;
- its repositories are cloned as the launch cloned them: the same repositories at the same requested refs, with the same landing and git identity. Branches the agent pushed are not checked out;
- it gets `ExitSnapshot` under DL-084's rule.

**The import.** Once OpenCode answers, and before the session is `running`, each conversation of the session is imported in creation order. It is sent with its stored `Session.Info` and every stored message's `Raw`, oldest first. The import goes through the launcher's own connection to the sandbox, the one that waits for OpenCode to answer (DL-030), as a lifecycle write of the launch like a job's opening prompt. `withConnection` cannot be used, since it refuses a session that is not `running`. The imports together are bounded to 2 minutes, and a transcript run's launch deadline is `LaunchTimeout` plus that bound. An import that fails, or is not reached within the bound, is noted in the log as `spov.session.import.failed` with the conversation's ID, and the resume carries on: the transcript is still in the store and on the page, but the agent will not see it. The imported `Session.Info` carries the conversation's model, so a model switched while the session ran comes back with it (DL-087).

**The sequence.** For each imported conversation, two numbers are recorded on the conversation (`conversations.seq_base` and `seq_after`):

- `after`: the durable seq the import itself reached, read once from the conversation's log with `follow=false`. At the pin that answers only `{"type":"log.synced","seq":N}`, and N is the head (S-TR1, 2026-11-06: head 4, next turn from 5);
- `base`: the store's last seq for the conversation.

The recorder skips a transcript run's frames up to `after`, which are the import's echo of messages already stored. It stores each later frame at `base + (seq − after)`, so each conversation's stored sequence continues without collision, and the gap rule compares against the stored last seq as before. A later transcript resume replaces both numbers. A snapshot run keeps them, because its OpenCode store and durable log continue from the run it restores (DL-088). This amends DL-017's event identity and gap rule for imported conversations.

**What the recorder keeps.** Each item of the session listing the recorder already reads at attach (`GET /api/session`) is a whole `Session.Info`. The recorder stores it as `conversations.info`, as it keeps messages whole, and replaces it only with a listing item that differs. That adds no read (DL-018). A conversation recorded before this change has no info. For it the server builds one from what the store has (ID, title, directory, times, and zero cost and tokens, which the schema requires). S-TR1 showed a built info imports every message, and the model is sent the history.

**The agent is told.** The generated `AGENTS.md` gets a section saying the session was resumed from its transcript: the workspace is a fresh clone, and uncommitted changes, installed packages and files the earlier runs wrote are gone. A later snapshot resume drops it (DL-088).

**The contract.** The import endpoint and the log-head read go into `contract.Used`, with a wrapped fake (DL-035). S-TR1 joins the OpenCode-bump checks:

```
SPOV_PROBE=1 go test -tags integration ./internal/server/ -run STR1 -v
```

## Rationale

The transcript is what spov always has on a hosted server, so this path makes every interactive session resumable, whatever happened to its sandbox. Cloning as at launch is the only state spov can rebuild faithfully, and saying so (DL-090) is better than guessing which pushed branch the agent meant.

Importing before `running` means a first message (DL-087) never reaches a conversation that is still empty. Offsetting the sequence keeps one stored log per conversation, which is what the page, the listing and the gap rule already read, rather than splitting a conversation's rows by run. Keeping the info whole costs nothing extra: it comes with the listing the recorder already reads.

## Consequences

- A migration adds `conversations.info`, `seq_base` and `seq_after`.
- The import endpoint is experimental in OpenCode, and the contract check and S-TR1 are its guards on a bump. If it goes away, transcript resume still gives a fresh sandbox with the old transcript readable on the page, and the import failure is noted.
- How large a conversation the import takes is unmeasured. Implementation measures it with the long-conversation fixture behind `TestIntegrationMeasureLongConversations` (DL-070), and the 2-minute bound is checked against that.
- The recorder half (`conversations.info`) is worth shipping first, so that sessions recorded before resume lands already have their info.
