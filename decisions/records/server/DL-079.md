## Context

spov has a goreleaser configuration that cross-compiles in CI but publishes nothing, and the README installs from source. Distribution (part 3 of the GitHub-move plan, researched 2026-11-04 against Claude Code, OpenCode, the GitHub CLI, Coder and Woodpecker) agreed on published releases with signed checksums and attestations. DL-077 left one check to this work: a published binary must embed the credential proxy, or a server launches sandboxes with their tokens in the main container or refuses routed credentials.

## Decision

- **A tag makes a release.** Pushing a tag `v<semver>` runs `.github/workflows/release.yml`, which runs goreleaser `release` on Linux. The release is created as a **draft**, so a person publishes it after looking at it; nothing is published by the workflow alone.
- **What it holds:** `spov_<version>_<os>_<arch>.tar.gz` for Linux and macOS on amd64 and arm64 (as `.goreleaser.yaml` already builds), `checksums.txt`, its Sigstore bundle `checksums.txt.sigstore.json` (goreleaser's `signs`), and `install.sh` (DL-080).
- **Signing:** `checksums.txt` is signed with cosign keyless signing through GitHub Actions' OIDC token (`cosign sign-blob --bundle`), so the signature names the workflow and the tag that made it, and no key exists to leak. Every archive also gets a GitHub artifact attestation (`actions/attest-build-provenance`), checkable with `gh attestation verify <archive> --repo jimutt/spov`.
- **The release check:** before goreleaser publishes, the workflow runs `scripts/release-check.sh` on the built Linux amd64 binary. It refuses the release when the binary embeds the web app's placeholder page or `internal/proxybin`'s placeholder instead of the proxy (`spov version --embedded`, which reports both), or when its version is not the tag. This is DL-077's release check.
- **Versions:** the tag is the version (`internal/version`, stamped by goreleaser). A prerelease tag (`v0.3.0-rc.1`) makes a prerelease.
- **Permissions:** the workflow asks for `contents: write`, `id-token: write` and `attestations: write`, and nothing else.

## Rationale

Keyless signing ties a release to the workflow that built it without a long-lived key, which is what the other projects researched do. A draft keeps a person between a tag and a public release, which matters while spov is pre-release. The release check makes the two embedded parts impossible to forget, since a release built without either works and looks normal.

## Consequences

- A maintainer releases with `git tag v0.1.0 && git push origin v0.1.0`, then publishes the draft.
- `spov version --embedded` exists, and the check depends on its output.
- Tests: `TestVersionReportsWhatIsEmbedded`, and `TestTheReleaseCheckRefusesAPlaceholderBuild`, which runs the check against stand-in binaries. A local rehearsal (`goreleaser release --snapshot --skip=publish,sign --clean`) built every archive and the cask on 2026-11-06. `docs/releasing.md` is the maintainer's account.
