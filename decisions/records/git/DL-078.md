## Context

Forges run package registries of their own: GitLab's per project and group, Forgejo's and Gitea's per owner, GitHub Packages on separate hosts. A project that depends on a package from its own organisation's forge registry fails in a sandbox today: the proxy sets the forge token only on the session's repositories' git and API endpoints (DL-034), and GitHub Packages lives on other hosts. A routed credential (DL-072) could carry a second copy of the token, but the session already holds the forge's credential.

## Decision

A forge token is also set on reads of its forge's package registry, scoped to the session's own namespaces. Publishing is not allowed.

- **GitLab:** `GET` and `HEAD` under `<base>/api/v4/projects/<project>/packages/` for a session project (by its whole path or a recorded numeric ID, as DL-034's GitLab policy addresses projects), and under `<base>/api/v4/groups/<group>/-/packages/` for a group, by its whole path, that is a session project's namespace or one of its parents; a numeric group ID only with git access `all`, since a launch records no group's. The instance-level endpoints (`<base>/api/v4/packages/...`) name a package, not a project, and get no credential. The token is a bearer, as on the rest of GitLab's API.
- **Forgejo and Gitea:** `GET` and `HEAD` under `<base>/api/packages/<owner>/` for an owner of a session repository.
- **GitHub:** GitHub Packages accepts only a classic PAT, not an App installation token or a fine-grained PAT. A session whose GitHub credential is a classic PAT (prefix `ghp_`) gets it on reads of `npm.pkg.github.com`, `maven.pkg.github.com` and `nuget.pkg.github.com` for the session repositories' owners (the first path segment, or the npm scope). These hosts are then decrypted, added to the CA's names and to egress. A session on an App token or a fine-grained PAT gets nothing there, and `docs/forges.md` says to route a classic PAT as a routed credential instead (DL-072). `ghcr.io` is deferred with the Docker preset (DL-076).
- With git access `all` (DL-043), the namespace rule is lifted for that platform, as the repository rule is, and the read-only rule stays.
- The rule is `internal/credproxy/packages.go` (`allowsForgePackages`, `allowsGitLabPackages`), consulted before each forge's own policy. A package path segment may be escaped only as `%2F` or `%40`, which npm's scoped names use, and no segment, escaped or decoded, may be empty or a dot segment, so a read cannot climb out of the namespace it names (`packageSegment`). npm on GitHub gets a bearer, Maven and NuGet Basic. A classic PAT's package hosts are its platform's (`Platform.PackageHosts`), so they are decrypted and named by the CA, and the launcher adds them to the main container's and the sidecar's egress.

A spike should measure the paths and the presentation against the clients (npm, Maven, pip) and real registries, as S-GL1 does for glab, with a GitLab test token and `scripts/forge-test-server.sh`'s Forgejo. It has not been run: the paths follow each forge's documented package API, and whether GitLab's package endpoints take a PAT as a bearer for every format (its documentation names `Private-Token`, Basic or a deploy token for some) is unverified. A format that refuses it is the first thing to check if a package read fails with the forge's own token.

## Rationale

The session's own namespaces are where its own packages live, and reads are what a build needs. Publishing a package creates something that outlasts the session and that other projects then consume, which is a wider act than a push to a branch. It can be added later, per forge, if a job kind needs it.

GitHub is mostly out because of GitHub's own rule, not spov's. Supporting the classic PAT keeps the one case that works, and the docs point everyone else to a routed credential.

## Consequences

- A GitLab or Forgejo project that consumes its own group's packages builds in a sandbox with no extra credential.
- A session on a GitHub App sees a 401 from GitHub Packages, as it does today.
- Tests: `TestAGitLabTokenReadsItsOwnPackages`, `TestAForgejoTokenReadsItsOwnersPackages`, `TestOnlyAClassicPATReadsGitHubPackages`, `TestAClassicPATsPackageHostsJoinTheEgress`. `docs/forges.md` is the reader's account.
