## Context

DL-096 lets a session's environment carry variables from the user file, a project file and `--env`. They reach every process in the main container, spov's entrypoint included, which clones the repositories, writes git's credentials and identity, installs the proxy's CA and starts OpenCode before the agent runs. A project file can come from a repository someone else wrote. The agent can already set anything in its own shell, so these checks are not containment. Their purpose is that no variable can silently break what spov sets up, or change how spov's own setup and OpenCode's authentication behave.

## Decision

### Refused names

A name is compared without regard to case. It is refused if any of the following holds.

- **spov sets it.** This is computed, not listed: every name `opencode.EnvConfig` produces for the session (`PATH`, `HOME`, the add-ons' variables, the proxy's `credproxy.MainEnv`, each routed credential's placeholder, the provider key variables `prep.ProviderKeyEnvs`, `OPENCODE_PASSWORD`). A new variable spov sets is therefore refused without anyone updating a list.
- **It has a refused prefix:** `SPOV_` (spov's own), `GIT_` (git's configuration, such as `GIT_CONFIG_*`, `GIT_SSH_COMMAND` and `GIT_ASKPASS`, which would change spov's clone and credential helper), `LD_` (the dynamic loader).
- **It is a shell, proxy or trust-store variable:** `BASH_ENV`, `ENV`, `SHELLOPTS`, `BASHOPTS`, `IFS`; `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, `NO_PROXY`; `SSL_CERT_FILE`, `SSL_CERT_DIR`, `NODE_EXTRA_CA_CERTS`, `REQUESTS_CA_BUNDLE`, `CURL_CA_BUNDLE`, `JAVA_TOOL_OPTIONS`.
- **It overrides a forge CLI's credential or host:** `GH_TOKEN`, `GITHUB_TOKEN`, `GH_ENTERPRISE_TOKEN`, `GITHUB_ENTERPRISE_TOKEN`, `GH_HOST`, `GH_CONFIG_DIR`, `GITLAB_TOKEN`, `GITLAB_ACCESS_TOKEN`, `GITLAB_HOST`, `GITLAB_URI`, `GL_HOST`, `GLAB_CONFIG_DIR`, `GITEA_TOKEN`, `GITEA_SERVER_URL`. The forge CLIs read their credentials from files spov writes, and these would outrank them (DL-021, DL-032).
- **It is an OpenCode variable in the refused set.** `OPENCODE_*` is allowed in general (`OPENCODE_LOG_LEVEL`, `OPENCODE_DISABLE_AUTOUPDATE`, `OPENCODE_DISABLE_FILEWATCHER`, and so on). The refused ones, read out of the 2.2.5 binary, are those that touch authentication, where OpenCode's configuration comes from, the model list, or its own process wiring:
  - `OPENCODE_PASSWORD`, `OPENCODE_SERVER_PASSWORD`, `OPENCODE_API_KEY` (the Console token's placeholder, DL-015);
  - `OPENCODE_CONFIG`, `OPENCODE_CONFIG_CONTENT`, `OPENCODE_CONFIG_DIR`, `OPENCODE_CLI_CONFIG_CONTENT`, `OPENCODE_CONFIG_PROJECT_DISABLE`, `OPENCODE_DISABLE_PROJECT_CONFIG`, which replace or disable the config spov writes and with it a job's permission policy, the model declarations, the web search pin and the plugin (DL-038, DL-013, DL-039);
  - `OPENCODE_MODELS_URL`, `OPENCODE_MODELS_PATH`, which would make the model list differ from the one spov checks a launch against (DL-013);
  - `OPENCODE_CLIENT`, `OPENCODE_ROUTE`, `OPENCODE_SESSION_ID`, and the prefixes `OPENCODE_PTY_` and `OPENCODE_SSH_ASKPASS_`.

  The set is a list in code (`opencode.RefusedOpenCodeEnv`). A pin bump compares the new binary's `OPENCODE_*` names with the previous pin's and decides each new one, a step in AGENTS.md's "Bumping the pin" (DL-035).

### Shape and limits

- A name matches `^[A-Za-z_][A-Za-z0-9_]*$` and is at most 128 bytes.
- A value is at most 4 KiB and may not contain a NUL byte.
- A session takes at most 64 variables and 32 KiB of names and values in all, counted after DL-096's merge (the server's base included).

### Where it is checked

`opencode.CheckUserEnv` holds every rule. The CLI runs it on the merged map before contacting the server, so a bad project file fails at once and names the file's variable. The server runs it again on the request, and that check decides: a refusal is a 422 naming the variable and the rule. A server's own `sandbox.env` is checked when `spov serve` starts, which refuses to start on a bad one. The computed names are those of the session being launched, so the server's check is the complete one: the CLI cannot know every placeholder a launch will attach.

## Rationale

- Computing the names spov sets keeps the refused list from going stale as add-ons, routed credentials and providers are added.
- The prefixes and fixed names cover what changes how spov's own setup behaves before the agent exists, which a person reading a project file would not expect a variable to be able to do.
- Allowing `OPENCODE_*` by default keeps OpenCode's own flags usable; reviewing new names on each bump is the price, paid where the binary is already being examined.
- The limits are well above any ordinary use and keep a session row and the launch request small.

## Consequences

- A variable a user expected to set, such as `GITHUB_TOKEN` for a script, is refused with the rule named. The message points secrets to routed credentials.
- An OpenCode release that adds a harmful variable is caught only if the bump's review notices it.
- The refused list is part of the docs (`docs/configuration.md`) and must follow the code.
