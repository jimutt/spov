## Context

DL-034 gives a stored token, a Forgejo token or a GitHub PAT, to the proxy sidecar and adds it only to the endpoints of the session's repositories that `repoSections` allows, plus `POST /graphql` for a GitHub PAT. A request the policy does not allow is not refused: it is forwarded with the client's own credential headers removed, so it reaches GitHub anonymously.

For a GitHub PAT that leaves common `gh` commands unauthenticated. An agent that has opened a pull request goes on to check CI, and `gh run list`, `gh run view`, `gh run watch`, `gh run download`, `gh workflow list` and `gh search` use REST paths that are not in the list. On a private repository they answer 404. `gh run rerun` and `gh workflow run` answer `HTTP 401: Requires authentication` and tell the user to run `gh auth login`, and `gh run view --log` answers `HTTP 403: Must have admin rights to Repository`. Each reads as an expired or invalid token. The agent reported that it needed a refreshed token and could not fix it, and the session had to be stopped and resumed, though the PAT was fine. A GitHub App token is added on every path, so only a PAT session is affected.

`repoSections` is shared by GitHub and Forgejo/Gitea, whose `actions` APIs differ, so widening it would widen Forgejo too.

## Decision

A GitHub PAT, on `api.github.com` or `<host>/api/v3`, is also given its credential on these REST paths, reads only (GET and HEAD):

- below `/repos/<owner>/<repo>/actions/`: `runs`, `jobs`, `workflows` and `artifacts`, at any depth. This covers a run's jobs and logs and a workflow's runs.
- `/repos/<owner>/<repo>/releases`, at any depth, which includes a release's assets.
- `/search/<kind>` for any one segment `<kind>`, which names no repository.

The repository must still be one of the session's (or any, under git access `all`), except for search.

Everything else below `actions` stays refused by absence: secrets, variables, runners, permissions, OIDC and caches. Every write stays refused, so a rerun, a cancel and a workflow dispatch still fail. Releases created through the REST API and the uploads host stay refused.

The rules are GitHub's own (`allowsGitHubAPI`) and `repoSections` is unchanged, so Forgejo, Gitea and GitLab get nothing new.

## Rationale

- The refusal of Actions was never a decision about runs: DL-034 names secrets and variables as what it refuses, and the rest was absent only because nothing listed it. The reads stay inside the session's repositories and change nothing, and a run's logs and artifacts and a release's assets are what a person with the token could read anyway; they can hold material that is not in the repository, such as a workflow's build output, but nothing from secrets or variables.
- Search names no repository, as GraphQL does not, and DL-034 already gives a GitHub PAT GraphQL, "whatever its owner gave it". Search through REST adds no reach beyond that, and `gh search` needs it.
- Reads only, because a rerun or a dispatch changes what runs on the owner's account and a dispatch can start a workflow that uses the repository's secrets. A write that fails shows as a 401, which is the symptom this fixes, so the guide says what it means (DL-108).
- Alternatives rejected: adding `actions` to `repoSections` (widens Forgejo and Gitea, and any method); forwarding a refused request with a message instead (the proxy cannot know a 401 is its own doing); renewing the PAT (nothing to renew, a stored PAT is the secret itself, DL-021).

## Measurements

- Seen in a running spov sandbox with a stored PAT through the sidecar: `gh api` on `/user`, `/repos/<o>/<r>`, `/repos/<o>/<r>/pulls/N` and `graphql` answered with `X-Ratelimit-Limit: 5000` (authenticated), and on `/actions/runs`, `/actions/workflows` and `/releases` with 60 and on `/search/issues` with 10 (anonymous). `gh run rerun` and `gh workflow run` answered `HTTP 401: Requires authentication`, `gh run view --log` `HTTP 403`. The same requests are what `TestAGitHubPATGetsReadOnlyActionsReleasesAndSearch` asserts.

## Consequences

- `gh run list`, `view`, `watch`, `download`, `gh workflow list`, `gh release view` and `gh search` work on a private repository with a PAT.
- `gh run rerun`, `gh run cancel` and `gh workflow run` still fail in a PAT session, with a 401.
- Search is not narrowed to the session's repositories, as GraphQL is not. The PAT note on the session page, the launch log's line and `docs/forges.md` name search beside GraphQL (`PAT_GRAPHQL_NOTE`, `ProxiedTokenNote`), and `docs/forges.md` lists the new reads.

## Known gaps

- A run's logs and an artifact are served from a pre-signed URL on another host, which gets no credential and is outside the decrypted hosts. Under an `install` or `agent` egress preset that host may not be reachable. Not measured.
