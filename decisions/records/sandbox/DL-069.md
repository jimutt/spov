## Context

The CLI accepts and validates `sandbox.egress_extra_domains` from the user and project files, and `docs/configuration.md` lists it beside `egress`. But `spov fly` and `spov jobs create` send only the preset's name, and the server adds only its own `EgressExtraDomains` (`egressFor`; DL-031). A user cannot add a domain their toolchain needs from their own config, and the key does nothing on the client.

## Decision

Proposed, one of:

1. The request carries the extra domains, validated as the server's are and capped in number, and the server adds them to the preset; or
2. the key is server-only: the CLI refuses it in a user or project file, and the docs say so.

The first serves a user whose project needs one more registry; the second keeps every egress widening in the operator's hands.

## Consequences

Either way, the key stops being accepted and silently ignored.
