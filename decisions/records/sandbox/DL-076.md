## Context

A routed credential (DL-072) puts a placeholder in the sandbox, but a package manager reads its credential from its own config file, not from a variable. Naming a host and a scheme by hand is also easy to get wrong per registry. Two clients need more than a credential: Maven ignores `HTTPS_PROXY`, and Java trusts its own CA store rather than the system bundle, so a JVM fails TLS on every host the proxy decrypts, forge hosts included (DL-034).

## Decision

### The presets

A preset is a routed credential with its scheme and hosts filled in, plus a config file the entrypoint writes with the placeholder. It stores the same kind of credential; anything else is a host and a scheme by hand. The route's host is the host of the preset's URL.

| preset | options | scheme | written in the sandbox |
|---|---|---|---|
| `npm` | `--url` (registry), `--scope` (optional, `@acme`) | bearer | `~/.npmrc`: `//<host>/<path>:_authToken=${SPOV_CREDENTIAL_<NAME>}`, and `<scope>:registry=<url>` when a scope is given. npm, pnpm and Bun read it. |
| `maven` | `--url` (repository), `--id` (the repository's id in the project's `pom.xml`, default the name), `--user` | basic | `~/.m2/settings.xml`: a `<server>` with that id, the user and the placeholder as the password, and a `<proxies>` entry for `proxy:3128` with `localhost`, `127.0.0.1` and `main` as non-proxy hosts. |
| `nuget` | `--url` (the feed's `index.json`), `--user` (default `spov`) | basic | `~/.nuget/NuGet/NuGet.Config`: the source under the credential's name and its `packageSourceCredentials`, with the placeholder as `ClearTextPassword`. |
| `pypi` | `--url` (the index's `/simple/` URL), `--user` (default `__token__`) | basic | `~/.config/pip/pip.conf` `extra-index-url` and `~/.config/uv/uv.toml` `[[index]]`, each with the user and the placeholder in the URL. |

- The path of a preset's URL becomes the route's path prefix, so a credential for one repository on a shared Artifactory or Nexus host is set only below that repository (DL-072's paths). `--path` may widen it to a prefix that holds the URL.
- `maven`'s settings file is written whole, with one `<server>` per Maven credential the session holds and one proxy entry. A repository's own `settings.xml` is not touched; Maven reads the user file beside it. `pypi` adds an extra index, never replacing PyPI, and `npm` without a scope adds only the token line, so the project's own `.npmrc` still decides the registry.
- The files hold only placeholders and are written by the entrypoint from the session's `EnvConfig` before the clones. The entrypoint writes each file only when the session holds a credential with that preset.
- `docker` is deferred: the sandbox has no Docker daemon. A user can still route a registry's host by hand for tools such as `crane` or `skopeo`.

### Java trusts the sandbox's CA

Whenever the sandbox has the proxy, the entrypoint writes a trust store holding the system bundle and the sandbox's CA, and sets `JAVA_TOOL_OPTIONS` so every JVM reads it (`-Djavax.net.ssl.trustStore`, with its type and password) and also uses the proxy (`-Dhttps.proxyHost=proxy -Dhttps.proxyPort=3128` and `http.nonProxyHosts`). This covers Gradle and other JVM tools as well as Maven, which also gets the `<proxies>` entry above. A recreated sidecar with a new CA rewrites the trust store with the CA install exec (DL-034); a running JVM keeps the trust it started with.

### Measured, not assumed

Each preset is checked through a real sidecar by an integration spike in the style of S-K1 (`-run RoutedPresets`, local Docker, no Modal): npm, pnpm and Bun install a scoped package; Maven and Gradle resolve an artifact; `dotnet restore`; pip and uv install from an extra index; each against a test registry that requires the credential. The spike also proves that a JVM reaches a forge host through the proxy with the trust store. A preset whose client turns out to need a different file or option is changed here before it ships.

## Rationale

The four presets cover the registries the plan names and that organisations actually run. Each is little more than the client's documented config with a placeholder, which is why it is a preset and not a new kind of credential. A preset writes the user-level file, never the project's, so the repository's own config keeps deciding which registry a project uses.

Java's trust store is fixed for every JVM rather than only for Maven, because any JVM in the sandbox fails on a decrypted host today. That is a gap in DL-034, and routed credentials are what make it matter.

## Consequences

- A user adds a private npm registry with one command and `npm install` works in the next session.
- Every JVM in a sandbox with the proxy prints "Picked up JAVA_TOOL_OPTIONS" to standard error, which Java does for that variable.
- Yarn Berry (`.yarnrc.yml`), Poetry's own credential store and Gradle's project-level credential properties are not written. They can read `SPOV_CREDENTIAL_<NAME>` from their own config.
- Tests: `TestEachPresetWritesItsClientsConfig`, `TestAPresetsURLPathBecomesItsPrefix`, `TestTheJavaTrustStoreHoldsTheSandboxCA`, and the `RoutedPresets` spike on a client or image bump.
