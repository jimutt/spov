## Context

OpenCode installs a plugin from the npm registry at a session's first conversation. Under the `agent` egress preset (DL-031) the registry is refused, and a session configured with plugins then ran without them and without a word: measured in a Modal sandbox, where `envsitter-guard` and `opencode-rules` were simply absent and `registry.npmjs.org` failed its TLS handshake. `install` already admits the registry, and `open` admits everything.

## Decision

- When a session's request lists `sandbox.plugins` (DL-171) and its egress preset is `agent`, its egress also admits `registry.npmjs.org`, at launch and again for a resumed run, and the launch's progress says so.
- Nothing else is added for a plugin: a plugin that calls hosts of its own (a telemetry endpoint, a model download) needs them in `sandbox.egress_extra_domains`, and the docs say so.
- A repository's own `opencode.json` plugins are read by OpenCode after the clone, so spov cannot see them at launch; under `agent` they need the registry added by hand, and the docs say so.

## Rationale

A person who asked for plugins and for `agent` egress wants both; refusing the one host that installs the plugins only makes the first silently cancel the second. Admitting the registry is not free: the agent can then install any package, which runs code, and could publish to it, a way out for what it holds. That is the same opening `install` makes and that a request's own `egress_extra_domains` can make, and with the credential proxy the sandbox holds no secret to publish.

## Consequences

- `TestAPluginSessionReachesTheRegistryUnderTheAgentPreset` guards it.
