## Context

`resolveErr` in `internal/sandbox/modal.go` is documented to return a by-name lookup's `InvalidArgument` (a Modal environment that does not exist) as a real error (DL-029). But `isNotFound` also matches `codes.InvalidArgument`, so on both paths it becomes `ErrNotFound`, and `spov attach` or `spov stop` would say there is no such sandbox when the configuration is wrong. The integration test pins only the three not-found cases.

## Decision

`resolveErr` decides for itself: a `NotFound` (or the SDK's `NotFoundError`) is a missing sandbox on either path, and `InvalidArgument` only on the by-ID path, where it means a malformed ID. `isNotFound` is left as it is, since the image and sidecar lookups that also use it were measured with it (`TestResolveErrKeepsABadArgumentByName`).

## Consequences

A wrong `MODAL_ENVIRONMENT` reads as a configuration error rather than as a session that has gone.
